## 2. 已确认的边界

- 当前优先单人使用与多个工作区；2026-10-18 用户确认移除应用密码，暂只允许本机回环访问。经过认证的局域网访问保留为后续目标，现阶段关闭；数据归属与授权边界保留。
- Linux、Windows、macOS 均纳入原生运行设计。首先在 DGX Spark 上实测，其他平台逐项完成验收；不能把设计覆盖写成已经支持。
- 前端为本地 Web 工作台。主后端采用模块化单体，API 与后台任务执行进程分开。LangGraph 是唯一的 agent 编排运行时。
- 每个根任务最多保留 3 个未释放的子 agent 名额，初始子 agent 深度为 1。模型推理并发单独控制，Spark 初始为 1，测量后再调整。
- 当前模型是项目内的 Qwen3.8-Flash-Next-NVFP4；架构允许其他本地模型和经用户配置的远程 API。
- 不引入向量数据库。长期记忆以 Markdown 为主，任务状态、索引元数据和统计采用普通数据库。
- 原生安装和运行优先，不要求整个项目使用 Docker。个别执行沙箱可以提供 Docker 适配器。
- 已调研的搜索、文件、浏览器、桌面控制、多 agent、数据看板和交互式 UI 均纳入本版实施路线。重依赖按需安装，外部访问和设备控制按用户配置及授权启用。
- 最终设计、跨模块整合和验收由主 agent 亲自完成。辅助 agent 的研究和章节材料不构成整体验收依据。

## 3. 文档中的四类信息

1. **确认需求**：用户已经确定的目标和约束。
2. **设计决定**：本方案为实现需求作出的选择，开发应遵守；变更时更新对应决策及受影响文档。
3. **外部依据**：官方文档、开源仓库和已有调研事实，带来源与适用边界。
4. **待运行验证**：依赖本机硬件、版本组合、操作系统或真实交互才能确认的行为。

“支持”必须写明层级。例如“解析库列出 PDF”不等于“当前安装已具备 OCR”，也不等于“某个模型能直接理解 PDF 中的全部图表”。

## 4. 规格的权威位置

- 功能范围、用户行为和功能编号：需求文档。
- 模块职责、依赖方向、进程拓扑：总体架构。
- 实体标识、任务状态、事件信封、通用接口约定：运行时与数据契约。
- 模型能力、上下文组织、记忆规则、统计口径：模型、上下文与记忆。
- 工具返回值和错误恢复：工具、权限与恢复。
- 文件与控制设备的专用契约、前端交互：文件、电脑控制与界面。
- 当前实现、审查修复、已验证流程与剩余条件：[实现与验收状态](implementation-status.md)。
- 安装平台矩阵、运行验收方法：部署、维护与验收。

其他章节引用这些定义，不另起一套同名字段或状态。发现冲突时先修正规格，再实现；适配第三方协议时通过转换层保持内部契约稳定。

## 7. 常见术语速查

| 术语 | 在本项目中的意思 |
| --- | --- |
| Schema / 契约 | 数据有哪些字段、类型、限制，以及生产和消费双方必须遵守的行为 |
| Adapter / 适配器 | 将工作台统一接口转换成某个模型、工具或系统的真实调用 |
| Checkpoint / 检查点 | 保存任务执行到哪里及恢复所需状态；不等于一段文字总结 |
| 幂等 | 重复同一个逻辑请求不产生额外业务效果；必须有去重键或底层条件保证 |
| Lease / 租约 | 有期限的执行或资源使用权，续租失败后不能继续提交新动作 |
| Fencing / 代次隔离 | 用递增版本拒绝过期 Worker 的提交；不能自动撤销外部世界的动作 |
| Outbox | 在业务事务中保存“提交后要发送的通知”，随后可靠投递并去重 |
| Artifact / 产物 | 带归属、版本和来源的文件对象，例如原件、截图、日志和导出文件 |
| SSE | 后端持续向浏览器推送事件的通道；持久化和历史回放由工作台实现 |
| RPO / RTO | 恢复时可接受的数据时间缺口 / 恢复所需时间，必须根据实际演练确定 |

详细定义以对应技术章节为准。读不懂某个缩写时可先回到本表，再沿文档链接查看它的输入、输出和失败行为。
