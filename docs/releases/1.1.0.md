# RDesk 1.1.0

本版集中更新 Agent API、对话过程展示、项目配置和任务执行可靠性。

## 新增能力

- **对话过程与文件变更：** 处理过程直接按时间线展示；最终 AI 答复定稿后统一折叠为可展开摘要。最终答案保持可见，文件变更提供实际记录的增删行数与逐文件 diff，采集不完整时明确标注。
- **对外 Agent API：** 在设置中发布选定模型、工具与只读来源快照，通过独立 Bearer 密钥和调用方授权执行持续任务，支持提问、事件流及文件下载。监听默认关闭；非回环直连需要 TLS。当前不对外开放 host shell、电脑操作、MCP 或媒体生成，具体以能力目录为准。
- **用户目录与项目配置：** 设置中显示服务所在机器的实际数据目录；项目可通过 `.rdesk/config.json` 声明解释器、检查命令和运行偏好。新任务冻结已校验配置，项目文件不构成新的权限授权，也不迁移既有用户数据。

## 执行可靠性

- 常规单轮输出默认 8192 token；新任务另留一次 2048 token 恢复额度，可设为 0 关闭。恢复继续受连接、上下文、任务树预算和硬截止限制。
- 修复原生工具历史重放、缓存观察和截止前收尾；未完整提交的工具调用不会执行，失败或取消时按真实操作账本显示工作台摘要。
- 文件版本、原文匹配和容量预检提前到模型审核之前；提交时仍核对实际状态。审核提供有界变更证据，明确区分原有接口和本轮新增内容。
- 同一 owner Run 中已批准新建的普通文件，在版本链、规则和用户要求未变化时可复用创建授权；每次仍保留审批来源，不扩大已有文件、命令、子任务或外部调用权限。
- 内部变更快照按引用释放，并纳入会话删除流程；用户项目原文件不随会话清理。

## 验证与限制

直接相关的隔离数据库、协议、授权和回归检查已通过。真实 Chrome 与本地 Qwen 验证了桌面/390px 界面、处理过程折叠、文件审核、一次输出恢复、项目配置和本机 Agent API 调用。

Aider 同样前七题复测为 **6/7**，修复前为 **5/7**；七个有效 Run 均正常完成，没有观察到执行环境或评分基础设施故障。审核调用从 47 次减至 28 次，但累计任务耗时没有下降。唯一未通过题目为 book-store 的金额单位实现错误。样本很小，且中途断电重启影响缓存状态，不代表正式排行榜成绩或稳定性能提升。原始测试与候选仅保留在本机私有记录中。

Windows/macOS 完整安装、外部设备及公网域名/TLS 连通性、跨版本升级与回退仍待对应真实环境验证。详细证据边界见[实现与验收状态](../implementation-status.md)。

## 升级与发行范围

- 数据库迁移头为 **040_agent_api**。已有部署应先停服，准备与当前 schema 兼容的完整备份，再在受控环境中显式执行该版本的 `workbench migrate`；源码更新与解包不会自动完成迁移或切换服务。
- 产品内净化备份仍受既有媒体凭据及新增凭据字段的 schema 审核限制，不能视为当前 schema 的完整备份方案。使用已验证的运维备份/恢复流程，详见[发行说明](../../runtime/distribution/README.md)。
- Release 的源码 ZIP 包含预构建前端、双语 README、逐文件清单、SBOM 和许可材料；附带 SHA256 与构建报告。它不是完整离线或签名二进制安装器。
- 模型权重、用户文件、对话、数据库、凭据、本机部署清单和私有验收记录不随本版上传；本地既有部署清单保留。

## English

RDesk 1.1.0 adds collapsible completed activity with recorded file diffs, a separately authorized Agent API, user-directory visibility and `.rdesk/config.json` project declarations. It improves native history replay, output/deadline budgets, file preflight, review evidence and scoped reuse of newly created file approvals.

The Agent API is disabled by default; direct non-loopback access requires TLS. New tasks use an 8,192-token output budget and one configurable 2,048-token recovery allowance. The database migration head is `040_agent_api`; existing deployments require a verified backup route, controlled shutdown and explicit migration. Current product-backup and platform/network-validation limitations remain. Source archives include a built frontend, manifests, dependency/license materials and checksums, but no models, credentials or user data.
