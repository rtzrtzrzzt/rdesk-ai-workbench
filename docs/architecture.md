设计基线：2026-10-17。产品范围以[需求文档](requirements.md)为准，通用状态与接口以[运行时契约](technical/runtime-and-data.md)为准。

2026-10-18 运行增量：会话模块持有持久消息队列、归档/编辑锚点和可恢复删除意图；Thread 行锁串行化队列与 Run 准入，附件行锁与删除冻结串行化。LangGraph 每个工具后检查持久进展，32 轮阶段检查点自动让出 Worker 后继续；当前新任务默认单 Run 65536 轮、任务树524288次模型尝试，最终预算触顶暂停。独立审核使用同一模型许可、独立无工具上下文与真实用量记录，不占子 agent 名额，不扩大工具权限；高风险或本地审核不可用时交人工。会话和正文副本按冻结范围清理，使用 SDK 删除 Run 检查点，清理失败保持意图，不宣称删除完成。身份采用回环 bootstrap 加真实随机会话与 CSRF，当前禁用 LAN；保险库仍为独立进程和独立解锁边界。

附件交互增量：对话层自动准备原件输入，复用独立 file Worker 的有界处理与 UUID5 幂等任务；轮询不重复创建处理任务，失败或暂停后保留原文件引用。传输复用同一分块上传实现，异步回填绑定原草稿与认证代际。模型输入可携带原件 ID/版本与派生输入 ID/版本，服务端核对真实关系；未知二进制只编译为文件元数据，不伪造内容理解。外发边界沿服务端 `parent_id` 检查来源，截图派生件也不可外发。复杂处理仍由文件模块承担。

聊天活动增量：会话服务根据真实消息和工具 Operation 的持久时间戳提供分页活动；分支仅纳入选定历史实际引用的工具记录，未完成自有操作也能显示。概要不包含原始参数，详情按需读取。可见思考存入独立 `Message.reasoning`，与正文和同一 MVCC/SSE 游标一起恢复；provider 的 opaque、signature、redacted 数据仍仅用于私有协议重放。子任务 Thread 依据父 Run 标识，前端仅从主对话面板打开，不能与用户历史分支混淆。

快速引导增量：新用户输入先持久化，每个 Attempt 记录实际包含的输入 ID；生成监视器检查尚未纳入当前请求的新输入，取消当前未完成生成并重编译，保留已显示正文与思考，未完成工具调用不执行。子任务会临时让出生成资源供主任务响应引导，之后回到有序队列；模型许可仍为 1，新用户输入优先，其余按持久到达时间推进。已开始工具保持生命周期，待执行调用及过时问题/审批在安全边界被替换；等待子任务时可由新输入唤醒。接收、正在处理与成功调用中的投递分别展示，不能把接收确认当成模型已完成要求。

模型预算增量：`Generation.max_output_tokens=null` 时按总上下文减输入计数、原生媒体预留及协议余量安排生成空间，保留明确的可选上限。本机 SGLang 纯文本 Chat 使用同一服务聊天模板计数，其他情况显式回退为估算。子任务继承用户配置，不允许派遣模型任意压低预算。新默认轮次大幅提高，迁移仅提升等于旧默认值的保存设置，不改变冻结中的 Run。Chat 纯文本截断可持久接续最多16段，每段计真实 Attempt、重新排队；无正文、不完整工具或不能安全重放的协议仍暂停。超时按无生成进展计，不以持续正常输出的总时长截断；防重复、未知效果和停止边界保留。

持久压缩增量：Context 模块持有独立 `thread_contexts` 表，原始消息和 LangGraph 检查点仍分别保留。自动触发或手动请求在模型安全边界使用真实模型生成语义 STATE.md，计入独立 Step/Attempt/Usage；摘要完整生成、来源和所有权复核通过后才替换活跃窗口。跨任务复用摘要，工具调用与回执按完整组保留；记忆遗忘、原消息内容或接收方变化使摘要失效。无运行中的模型步骤时，手动压缩使用专用后台 Run，不创建用户消息或混入普通聊天任务列表。新用户任务可让出后台压缩，Steer 更新后重新整理，不覆盖新要求。

推理边界增量：提供方协议与 `engine_kind` 分开；引擎适配器负责已确认的思考参数、精确计数和定向取消。原生模型启动器抽出 SGLang driver，vLLM、llama.cpp、TensorRT-LLM 当前仅接入用户已运行的兼容端点，不安装、转换权重或声称通过本机推理验收。工具发现默认增量加载，显式 replace/remove 才缩减集合；整批工具身份校验失败时不执行该批调用，可进行一次不主动重放操作的模型纠正，再次失败则保留已显示内容并暂停。

## 1. 架构决定

采用 **React Web 前端 + FastAPI 模块化单体 + 独立 RunWorker + 独立模型服务**。业务模块在代码和数据责任上分开，首版共享一套后端发布物和 PostgreSQL，不要求每个模块单独部署。

“模块化单体”的含义是：模块有自己的公开接口、数据和规则，其他模块只能通过接口请求它做事；它们可以在同一进程中以函数调用协作。需要独立进程的长任务、模型和受控执行器按生命周期分开，而不是为每个类建立网络服务。

这能兼顾三件事：普通用户容易安装；主任务不受 HTTP 请求生命周期限制；以后某个重模块需要独立部署时，已有边界能够支持迁移。

### 1.1 运行拓扑

```text
本机或已授权的局域网浏览器
  └─ React / TypeScript 工作台
       └─ 同源 HTTPS/HTTP API + SSE 事件订阅
            └─ API 进程（FastAPI）
                 ├─ 账号、工作区、配置、资源访问
                 ├─ 接受命令、创建任务、接收答案与停止请求
                 ├─ 查询快照、产物和统计
                 └─ PostgreSQL：业务状态、事件、任务与检查点
                            ↑                   ↑
                            │                   │
                    RunWorker 进程        文件处理 Worker（按需）
                     ├─ LangGraph 唯一运行时    └─ 解析 / OCR / ASR / 转换
                     ├─ 上下文与模型网关
                     │    ├─ 独立本地推理服务
                     │    └─ 用户允许的远程 API
                     ├─ 统一工具执行器
                     │    ├─ 文件与进程执行器 / 可选沙箱
                     │    ├─ 搜索、网页、浏览器
                     │    └─ 桌面节点 / MCP 服务
                     └─ 记忆、交互、产物、用量服务

本地文件存储：原件、派生产物、日志、Markdown 记忆、规则和任务摘要
可选 Valkey：加速通知或协调；不成为任务和权限的事实源
Launcher：启动、检查与停止受管理进程，不承担 agent 决策
```

SSE 是服务器向浏览器连续发送事件的通道。浏览器发送命令仍用普通 HTTP。断开 SSE 不代表任务停止，也不应触发重新创建任务。

### 1.2 为何选择进程分离

- **API** 处理短请求，及时响应页面、停止请求和配置查询，不在 HTTP 请求中等待整段 agent 推理。
- **RunWorker** 领取持久任务并推进 LangGraph；Worker 重启后按照记录恢复。
- **文件处理 Worker** 隔离较重的 OCR、媒体解码和解析过程，避免阻塞任务控制。初期可以共用同一 Worker 发布物，以不同角色启动。
- **模型服务** 加载权重、管理 GPU 和推理缓存；普通页面重载不触发卸载权重。
- **执行器与桌面节点** 处理有副作用和平台相关的动作，其进程、权限、取消和清理均受统一管理。

服务健康必须分别报告：进程存活、数据库可用、任务可领取、模型加载中、模型就绪、具体工具可执行。一个 `/health` 返回成功不代表所有能力都可用。

| 层次 | 默认选择 | 使用边界 |
| --- | --- | --- |
| 前端 | React、TypeScript、Vite | Vite 用于开发和构建；发布使用静态产物 |

| 本地推理 | 适配当前模型的 SGLang 组合 | 版本组合先通过 Spark 基线，不等同于随意安装最新版 |

## 3. 分层与依赖方向

```text
展示与入口层：HTTP / SSE / CLI / 前端
                    ↓
应用层：完成用户动作的用例、事务边界、任务协调
                    ↓
领域层：状态机、预算、权限规则、能力规则、业务实体
                    ↑
基础设施适配层：数据库、文件系统、模型 SDK、MCP、OS、HTTP
```

领域层定义需要什么接口，不直接依赖某个模型 SDK 或桌面驱动。适配层实现这些接口。应用层负责组合，例如“提交任务”同时需要检查工作区权限、附件兼容性和预算，再持久化任务。

具体约束：

1. 路由函数只负责解析、认证、调用应用服务和映射响应，不直接编排 agent。
2. LangGraph 节点通过应用服务或稳定端口访问模型、记忆、工具，不直接读其他模块的表。
3. 前端不直接调用模型、MCP 或桌面节点，也不持有其密钥。
4. 提供方 SDK 类型只留在对应适配器内部；公共接口采用项目自己的稳定类型。
5. 模块可以调用另一模块公开的应用接口；避免相互调用。需要双向协作时由上层协调器组合，或通过持久事件通知。
6. 共享代码只放标识、时间、错误信封、分页和事务等稳定基础，不能把所有业务逻辑塞进 `common`。

## 4. 业务模块及所有权

### 4.1 Identity 与 Workspace

负责所有者账号、会话认证、工作区归属、项目目录登记和资源授权入口。首版一个所有者，但所有业务对象仍绑定归属；不能因为当前只有一个人就省略服务端权限检查。

公开能力：验证会话、取得当前主体、创建/查询工作区、判断主体能否对资源执行动作。以后加入成员关系时主要扩展授权实现，不要求所有工具重新解析组织字段。

### 4.2 Conversation 与 Run

Conversation 保存消息、分支和附件引用；Run 保存一次持续任务及步骤、预算、状态、取消和恢复。一次用户输入可启动一个 Run，一次 Run 可以调用模型很多次。二者不能用同一张“聊天消息”表代替。

Run 模块拥有任务状态机、任务命令、事件顺序和 Worker 领取机制。执行中的新用户输入作为持久输入事件注入当前运行，在安全边界处理；不会直接修改已经开始发送给提供方的请求体。

### 4.3 Agent Runtime 与 Collaboration

负责 LangGraph 的图定义、节点边界、检查点、根任务与子任务协调。主 agent 制定任务、分配上下文并整合，子 agent 在权限和预算内执行。

子 agent 管理模块负责槽位、父子关系、消息和结果，不拥有模型显存。调度模块另行授予模型生成许可，避免“3 个子 agent”被误解为“必须同时跑 3 份模型”。

### 4.4 Model Gateway 与 Capability Registry

Model Gateway 将内部请求转换成具体 API，处理流式事件、用量和错误；Capability Registry 保存连接能力、部署证据和用户策略。一个模型标识经不同推理服务暴露，可以有不同能力。

模型模块返回待执行工具调用，不执行工具。是否运行、是否允许、怎样隔离均由 ToolExecutor 决定，防止更换模型 SDK 时绕过安全边界。

### 4.5 Context 与 Memory

Context 负责规则、历史、记忆片段、附件、工具集合及上下文预算的编译。Memory 负责 Markdown 内容、索引、版本、候选写入和遗忘。长期记忆不等于全部聊天历史，任务 `STATE.md` 不等于 LangGraph 检查点。

PromptCompiler 对提供方生成最终请求；CachePolicy 只影响缓存相关参数和稳定组织，不负责改变真实权限或筛除最新用户要求。

### 4.6 Tool Registry、Policy 与 Executor

Registry 声明工具定义与版本；Policy 判断当前主体、工作区、任务和设备是否允许执行；Executor 统一校验、登记操作、选择隔离环境、执行、取消、存档和返回。

任何内置工具、MCP 工具、桌面动作和生成式 UI 回调都经过同一授权入口。工具注解和模型输出不能自行授权。

### 4.7 Search、Files、Artifacts、Browser 与 Desktop

- Search 负责检索和网页来源，支持更换搜索提供方。
- Files 负责上传、格式检测、转换和提取，操作输入的受控引用而非模型随意指定的主机路径。
- Artifacts 负责原件、版本、派生关系、下载授权和预览元数据，不负责理解内容。
- Browser 负责浏览器会话和页面观察/动作。
- Desktop 负责设备配对、系统能力、屏幕观察、动作租约和人工接管。

Browser 与 Desktop 共用工具执行契约，但设备生命周期与权限不同，因此保持两个模块。原生文档处理不必先调用桌面应用；需要真实 GUI 流程时再使用桌面工具。

### 4.8 Interaction 与 Presentation

Interaction 保存问题、答案、授权请求和中断恢复条件，保证刷新或重启后仍能继续。Presentation 将业务事实转换成稳定前端事件、卡片或受控 UI 描述。

AG-UI 是一种对外事件适配方式，A2UI 是组件描述方式。它们不拥有任务、问题或权限的数据库事实。提供方把等待用户表达为“运行结束事件”时，适配器必须映射回工作台的等待状态，不能误判业务完成。

### 4.9 Usage、Telemetry 与 Settings

Usage 保存按调用尝试计量的事实、估算来源和价格快照；Telemetry 提供事件、性能和设备指标；Settings 提供版本化配置及生效范围。

业务成功不能依赖外部遥测平台写入成功。后台导出失败可重试，但不能导致工具或模型调用重新执行。

### 4.10 Supervisor 与 Resource Scheduler

Supervisor 管理被工作台启动的进程、准备状态和优雅关闭，不擅自停止用户独立运行的外部服务。Resource Scheduler 负责生成并发、文件处理配额、桌面租约、工作区写入锁和预算。

不能把模型响应慢直接当作进程死亡重启。模型加载、请求排队和无响应分别有状态、超时与恢复策略。

```text
  features/               chat、files、memory、models、settings 等独立功能
  components/             共享基础组件
  api/                    OpenAPI 生成类型；手写 HTTP、下载与 SSE 适配

  entrypoints/            API/路由、Worker、CLI 与账户恢复入口
  modules/                runs、agent_runtime、collaboration、models、context、memory
                          tools、files、search、mcp、browser、desktop、automation 等
  infrastructure/         配置、数据库、凭据、访问边界与 OS 公共实现
  contracts/              公共错误、事件、账户与分页契约
  composition/            集中导入模块 ORM 声明，供迁移装配；不启动运行服务
apps/server/migrations/   Alembic 应用 schema 迁移
scripts/
  bootstrap.py            项目原生准备与启动入口
  dev/                    原生 PostgreSQL、开发和运行辅助
  model/                  独立模型监管与验收脚本
  services/               搜索、文件与自动化组件入口
  contracts/              OpenAPI 导出
  release/                源码发行、SBOM、校验与暂存

```

模块按真实复杂度拆分 `domain.py`、`service.py`、`dto.py` 和适配器；没有为所有模块机械创建五层目录。运行装配由入口承担，`composition/tables.py` 汇集迁移所需的 ORM 元数据；没有独立的 `apps/launcher` 或 `packages`，不将早期设计示意目录冒充现有源码。

Python 使用 uv 锁文件，前端使用 npm 锁文件。数据库与用户文件位于独立数据根；本机验收资料、截图、日志、环境和模型均不提交 Git。进程角色可以独立运行，但共享同一后端发布物和契约。

## 6. 核心端口契约

端口是业务需要的能力接口，下表列出职责而非第三方 SDK 的真实方法签名。具体字段见相关技术章节。

| 端口 | 输入与输出 | 必须提供的行为 |
| --- | --- | --- |
| ModelProvider | CanonicalModelRequest → 统一流事件和用量 | 能力映射、取消、提供方错误归一化 |
| ToolExecutor | ToolCall + ExecutionContext → ToolResult | 权限检查、操作登记、执行与恢复 |
| SandboxProvider | 权限范围 + 执行配置 → 执行会话 | 声明隔离能力、终止与清理 |
| SearchProvider | 查询 + 搜索配置 → 来源列表 | 超时、来源和分页/数量限制 |
| FileProcessor | 原件引用 + 处理计划 → 派生产物 | 能力检查、进度、定位、部分失败 |
| BrowserProvider | 会话 + 观察/动作 → 新观察或结果 | 会话隔离、陈旧目标检测、停止 |
| DesktopProvider | 节点 + 租约 + 观察/动作 → 结果 | 系统权限、单写者、坐标有效性、人工接管 |
| MemoryStore | 范围 + 查询/候选修改 → 命中/新版本 | 来源、版本冲突、遗忘与索引更新 |
| ArtifactStore | 归属 + 文件版本 → 受控引用或流 | 原件保护、引用校验、原子提交 |
| EventStore | 事务内事件 → 按序查询 | 去重、顺序、回放和快照边界 |
| ResourceScheduler | 资源需求 + 预算 → 许可或等待 | 公平排队、租约、取消、释放 |

端口返回项目自己的类型，并带适配器/协议版本。修改第三方 SDK 时，优先修适配器与契约测试，不向业务代码传播字段兼容特判。

## 7. 关键跨模块流程

### 7.1 发送任务

1. UI 上传附件或引用已有产物，取得受权限保护的 artifact_id。
2. API 校验账号和工作区，执行轻量能力检查，保存幂等请求、用户消息、Run、初始事件及待执行任务。
3. 事务提交后返回 run_id。网络丢失时可用 request_id 找回，不重复创建。
4. Worker 取得租约与版本，加载配置和规则快照，规划必要的文件转换。
5. 取得整实例生成许可后，Context 重新读取当前输入、记忆和权限并编译，再由 ModelProvider 发起请求；每次重试重新编译，避免排队期间新增输入或撤权被旧请求覆盖。
6. 模型返回文本或完整工具调用。工具通过 Executor 执行，结果持久化后供下一步读取。
7. 需要用户输入时保存问题和检查点，释放可释放资源；回答被原子接受后恢复。
8. 完成时保存最终消息、产物和用量，执行清理并进入终态。

### 7.2 子 agent 协作

主任务先持久化子任务目标并原子预留名额，再入队。子任务获得自己的 run_id、上下文快照和预算，引用同一个 root_run_id。它们共享模型服务而非复制权重。

主任务等待子任务时让出 Worker 的执行时段和模型许可，不能占用一个线程阻塞等另一个队列任务。子任务结果只是待主任务检查的材料；最终产物整合和验收由主任务承担。

### 7.3 文件写入与记忆更新

应用先登记操作与预期版本，再在范围内生成临时内容，完成检查后以原子替换提交单文件；记录新版本和事件。跨多个文件不承诺一个文件系统事务，逐个步骤有恢复记录。

版本检查与文档锁保证经统一服务的写入不会使用过期版本覆盖；不参与锁的外部编辑器仍可能产生竞争。检测到冲突暂停写入，严格保留原件的路径只生成独立候选；完整边界见[文件与数据库一致性](technical/runtime-and-data.md#7-文件与数据库之间的一致性)。

Memory 的候选提取不能直接编辑 AGENTS.md。记忆写入需经来源、重复、冲突、范围和版本检查；待写队列同时服从用户遗忘操作。

### 7.4 权限撤销与取消

权限是每次实际执行时重新检查的当前约束，普通模型参数则主要使用运行快照。撤销发生后，旧快照不能继续授权；对已经提交给外部系统且不可撤销的操作记录其实际状态。

取消是持久命令：先进入 cancelling，向模型、工具、子任务和执行器传播停止，核对清理状态，再发布终态。不能先显示“已停止”再继续执行后台命令。

## 8. 数据与配置边界

### 8.1 数据职责

- PostgreSQL：归属、配置版本、对话、Run、步骤、问题、授权、任务队列、事件、索引元数据、用量和 LangGraph 检查点。
- 用户数据目录：原始附件、派生产物、日志文件、长期 Markdown 记忆、规则和任务摘要。
- 项目目录：用户代码、项目 AGENTS.md、显式选择的项目资料；不自动写入所有内部任务日志。
- 模型目录：独立大资产，可以位于项目现有 `models/` 或用户指定位置。

初始运行数据根目录按平台选择 Linux XDG 数据目录下的 `ai-workbench`、macOS `Application Support/AIWorkbench`、Windows `LOCALAPPDATA/AIWorkbench`，允许用户在向导中指定。解析交给跨平台路径库，不能在业务中拼接平台常量。

### 8.2 配置合并

普通偏好按系统默认 → 用户 → 工作区 → 本次任务合并，保存最终配置和各字段来源。应用级硬限制、主体权限、平台能力和资源容量只允许进一步收紧，不能被任务覆盖放宽。

例如任务可把子 agent 上限从 3 降到 1，不能传入 10 绕过产品限制；用户在全局禁用外部上传后，某个工作区选择远程视觉模型也不能自动上传截图。

任务提交可省略模型以继承当前默认，但前端同时携带其已向用户展示的 `expected_model`（连接 ID 与版本）。服务端解析当前默认后在连接行锁内核对；发生变化返回冲突，由用户重新核对目标，尤其不能让附件确认绑定到另一远程连接。接受后冻结本次模型与普通生成参数；执行时继续读取当前权限和记忆。

每个配置项声明类型、默认值、范围、敏感性、依赖条件和生效时机。模型地址、协议等变化会使相关能力验证失效；普通主题设置无需重启任何模型。

## 9. 调度与资源约束

PostgreSQL 的持久任务表、事务和租约是默认调度基础。`LISTEN/NOTIFY` 或可选 Valkey 用于提醒“有新任务”，通知丢失仍可通过扫描恢复，不能把通知当任务本体。

至少独立控制以下资源：模型生成并发、子 agent 名额、CPU 文件处理、GPU 文件处理、工作区变更、浏览器会话写入、桌面写入、网络请求和任务预算。不要用一个全局并发数字控制所有行为。

Spark 为统一内存架构，模型、系统、缓存和部分处理任务争用同一池。当前所有模型连接共用一个数据库级生成许可，整实例并发固定 1，不能靠 URL 别名、重复连接或不同模型名绕过；OCR/ASR 与模型重负载是否可同时运行由实际内存和延迟基线决定。后台记忆整理优先级低于交互任务，但须有防止永久饥饿的调度机制。

单机使用同一数据库完成租约与配额事务，不需要先引入分布式锁服务。扩展多个 Worker 时仍通过所有者令牌和 fencing 版本阻止过期执行者提交结果；对于已经发出的外部副作用，另行核对，不能只靠租约宣称绝不会重复执行。

## 10. 安全与扩展边界

默认同源部署减少浏览器跨域和凭据暴露面。LAN 模式显式开启认证和部署提示；文件下载、事件订阅与 SSE 重连都检查归属，不能仅保护普通 JSON 接口。

插件注册由组合根管理，开启和关闭都有清理钩子。MCP 工具声明、网页文字、模型输出、动态 UI 和项目文件不具有管理员权限。模型通过类型化动作提出请求，授权由后端独立执行。

插件的版本、配置和错误有稳定边界。新增工具会改变提示词工具集合，按任务快照或安全边界重新编译；不能在一次模型流式调用中途偷偷更换 schema。

## 11. 长期维护与演进条件

只有出现实际独立扩容、权限隔离、发布节奏或依赖冲突需求时，才把模块拆成独立网络服务。优先候选是文件处理或桌面节点，本就具有独立生命周期；普通设置和工作区 CRUD 不需要微服务化。

变更流程：定位受影响需求 → 修改公开契约及版本 → 更新适配器 → 迁移数据与配置 → 验证上下游和真实流程。保留旧事件的读取能力，或者提供显式迁移，不能把数据库存档建立在“所有调用方总是同一最新版本”的假设上。

当前不建立多人协作和向量数据库的空壳实现。保留资源归属、MemoryStore 和检索端口已足够支持未来评估，不提前为假设功能增加维护负担。

最终的架构取舍、模块整合与验收由主 agent 亲自执行。辅助章节必须与本文件及通用契约一致，不能形成几套互不连接的设计。
