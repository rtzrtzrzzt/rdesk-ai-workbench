## 3. 架构与代码审查的闭环

维持模块化单体：HTTP/CLI 入口、应用用例、运行图、模型适配、工具、原生执行器和数据职责有明确边界；API、agent/file Worker、凭据伴随服务及可选自动化进程按生命周期分离。没有为了“企业级”改成微服务，也没有把所有模块改成万能服务。

三个审查分工覆盖运行/协作/迁移/进程与模型脚本，模型/上下文/记忆/文件/工具/搜索/MCP/自动化/沙箱/生成界面，以及前端/身份/配置/会话/访问边界/统计/原生发行。补查直接依赖与受影响迁移；前端相对依赖图没有发现循环。主 agent 对核心发现亲自修改并整合，监管辅助修改由主 agent 复核。该覆盖不是逐行无遗漏或零缺陷保证，也不是第三方库完整安全审计。

| 审查发现 | 当前修复与核对 |
| --- | --- |
| 末轮补充输入可能漏送、任务仍成功 | 持久输入 ID、成功 Attempt 投递凭证、压缩保留待送输入、完成事务再核对、END 快照重新排队；真实 UI 验证下一次调用及刷新一致 |
| 同一模型用 URL/名称别名绕过容量 | 所有模型尝试共用同一数据库许可，当前整实例固定容量 1；请求预算计数在许可内。源码及调用链核对，不冒充完整压力测量 |
| 排队/重试复用过期权限、记忆和输入 | 获得许可及每次重试后重新编译；冻结普通模型参数，动态权限继续收紧 |
| 取消树锁顺序与子任务收尾冲突 | 当前 root→agent→file 树按祖先顺序锁定；终态提交再次尊重取消/截止；源码定点复核 |

| 递归文件查找漏掉私有数据边界 | 每个候选重查实际 data_dir、模型根、排除项及符号链接；有界遍历与显式搜索文件集；实际临时文件和大文件尾部检索核对 |
| MCP 网络等待后沿用旧授权 | 目录刷新后、每次新 transport 和真正 call_tool 前重新检查当前门禁；多轮持久回执与现有流程保留 |

| SSE 快照覆盖增量、认证响应跨代 | 一致消息快照加事件游标；缺口/终态收敛；登录/注销代次及请求取消，旧响应不能发布新会话状态 |
| 模型默认继承/外发确认目标变化 | UI 继承时不写强制模型；提交 expected_model 连接 ID/版本，在服务端解析默认和冻结之间核对；变化明确冲突 |

| 模型辅助脚本受环境代理/重定向影响 | 共用明确禁用代理、仅回环、拒绝重定向的 HTTP 边界，原始结果私有权限；独立真实本地接收器验证 |

辅助检查包括 Ruff、TypeScript/Vite 构建、OpenAPI 类型生成、迁移/ORM 对照及针对上述缺陷的真实原生机制检查。前端构建保留现有较大主 chunk 提示，没有提高告警阈值掩盖；没有因该提示无故扩大重构。

## 4. 仍需条件的项目与最短验证路径

- **Windows/macOS**：需要真实设备。先完成原生安装、数据库配置和普通对话，再按平台验命令、进程取消、权限、截图和恢复；当前持久命令驱动明确不支持两平台，macOS 桌面输入也不开放。
- **桌面输入法**：当前 X11 type 仅可打印 ASCII。原 Chrome/libpinyin 环境收到 keyup 而没有实际字符 input；增加按键延时无效。仅新建目标 Chrome 使用进程级 `GTK_IM_MODULE=xim`、`XMODIFIERS=@im=none` 时成功，全局输入法未修改。目标应用须重新观察确认结果；不自动切换输入法、不自动补发或提交中文预编辑。
- **模型监管维护**：受管停机及真实重启后旧模型/命令记录核对已有第20节证据；随后恢复的固定模型实际运行结果见第21/22节。完整预编译、压力基准、所有故障时序和缓存自动轮换不据此视为完成；第5节及[模型说明](../runtime/model/README.md)保留对应阶段样本与限制。
- **OCR、Wayland、沙箱及自由脚本**：取得合适安全组件、Portal 驱动或实际隔离能力后验收；Spark bubblewrap 当前 `namespace_denied`。不可用功能明确拒绝，不静默退回宿主运行。
- **外部模型/原生视频**：需要用户配置真实提供方凭据或真实短视频样本，再逐能力验收。不通过付费隐藏探测、替换固定模型或伪造响应填补。
- **LAN 与发行**：第二台设备验证证书受信任、断线与会话撤销；另安排正式旧版本到新版本的迁移/失败回退。当前源码包不含全部运行依赖，也没有签名二进制/一键离线安装承诺。

当前仅支持与本版本 schema 匹配的隔离备份恢复，旧 schema 备份须先有明确升级路线；恢复的未结束任务为 held。上述缺口保持可见，后续只在获得对应条件或发生相关代码变更时补验，不重复已有效的全部流程。

**当前schema039的产品内备份限制**：维护服务按表列审核秘密排除范围，媒体表中的`media_connections.encrypted_api_key`及`media_tasks.encrypted_credential`尚未纳入该流程，因此返回`backup_secret_schema_unsupported`，不取决于是否存在凭据值。早期产品备份/恢复和后续私有运维PG归档是不同证据，不能合并声称当前schema已完成可移植产品备份。本次仅同步这个真实边界，不修改备份逻辑或执行备份。
