# AI 工作台需求文档

版本：设计基线 1.0，2026-10-17。阅读入口：[文档索引](README.md)。本文描述已确认的产品目标和验收条件；当前已实现与已验证的范围见[实现与验收状态](implementation-status.md)，不能从需求清单推定全部交付完成。

2026-10-18 用户确认的本轮调整优先于下文旧设计：应用免密码且暂限回环访问，局域网关闭，保留独立凭据保险库；默认智能风险审核，歧义、高风险与审核失败交人工；输出中默认 Queue，可选尽快调整当前生成的 Steer；会话编辑建新分支、归档恢复与确认范围后永久删除全部后代；真实文件版本化链接；搜索引擎目录勾选；长任务有进展可自动分段续跑，重复无进展与静默超时保留断点暂停，子 agent 不得继续派遣子 agent。

聊天展示增量：普通侧栏仅列用户对话，子 agent 的状态和对话在主任务内点击打开；聊天按真实顺序展示进度正文及工具状态，点击可读结果和详情，原始参数、编号和调试信息默认收起。正常聊天删除重复助手标签和运行诊断，技术记录移至后台任务。模型确实提供可读思考或思考摘要时，展示可展开入口，不生成虚构思考、不公开加密协议数据。输入、输出和轮次避免不必要的小额度；默认按模型总上下文安排生成空间，保留防循环、停止和安全边界。当前 Spark 已开启MTP并真实验证131072总窗口，推理并发仍为 1，任务与工具可交错推进，不能宣称三个模型同时推理。

## 1. 产品目标

建设一个用户能够自己部署、长期使用并自由更换模型的本地 Web AI 工作台。它既能进行普通对话，也能围绕一个持续任务读取文件、修改代码、搜索资料、调用工具、协调子 agent、请求用户输入并交付可查看的产物。

整体目标是本地部署的 Codex 类工作台，并争取在以下方面做得更好：用户能看懂任务为什么等待或失败；模型、工具和资源可配置；本地数据边界清楚；中断后能恢复；记忆可编辑和追溯；更换模型不会失去整个工作流程。不能只用功能数量或缓存命中率代表产品优劣。

### 1.1 服务对象与使用场景

- **个人开发者**：在项目中解释和修改代码、执行测试、查看差异、让子 agent 独立调查或实现受限任务。
- **本地 AI 使用者**：接入自己的模型和 API，处理文档、整理知识、搜索和写作，观察资源消耗。
- **需要自动化的用户**：让 agent 在明确目标和权限范围内操作浏览器或本机应用，必要时接管操作。
- **维护和扩展者**：新增一个模型提供方、搜索引擎、文件解析器或桌面驱动，不必修改整条任务链路。

首版以单个所有者为使用主体，允许多个浏览器设备登录同一账号，不包含团队协同编辑、组织计费、企业 SSO 或多租户托管服务。数据归属和授权边界必须存在，便于后续扩展。

### 1.2 已确认的产品约束

1. 本地 Web 界面，支持局域网经过认证的访问。
2. Linux、Windows、macOS 纳入原生运行设计；DGX Spark 是第一实际验收环境，其他平台逐项验收。
3. 模块化、接口明确、便于长期维护；首版采用模块化单体，而非强制微服务集群。
4. LangGraph 作为唯一 agent 编排运行时。
5. 每个根任务最多 3 个未释放的子 agent 名额；用户可把上限调低。初始不允许子 agent 再创建子 agent。
6. 不使用向量数据库，长期记忆以 Markdown 为主。
7. 支持本地模型和外部 API，模型输入输出能力独立配置。
8. 整个工作台不依赖 Docker 启动，Docker 仅作为部分沙箱的可选后端。
9. 优先采用成熟、热门、维护活跃且许可适用的开源项目；Stars 是参考，不替代兼容性和部署成本判断。
10. 分阶段实施和验收；代码、辅助检查与真实产品验收分别记录，未满足条件的可选能力保持明确的不可用或待验证状态。

## 2. 本版范围与功能交付方式

本版纳入下述全部需求。按实施顺序逐步完成，不要求用户一次安装所有重依赖。

- **基础安装提供**：工作区、模型连接、对话和任务、基础文件及进程工具、持久化提问、Markdown 记忆、设置和看板基础框架。
- **按需启用的功能模块**：联网搜索、浏览器自动化、复杂文档解析和 OCR、音视频处理、桌面控制、额外沙箱和智能 UI 渲染器。
- **受平台和模型约束的能力**：图像、音频、视频、原生 PDF 输入；GPU 推理；特定桌面驱动；隔离执行环境。必须通过能力探测与验收，不能用一个总开关声称全部可用。
- **为后续保留接口但本版不实现的范围**：组织与团队管理、多人同时编辑同一任务、公共插件市场、云托管计费、集群自动扩缩容、向量数据库与向量 RAG。

每个可选功能在界面显示“未安装、已安装但未配置、待授权、待验证、可用、不支持、故障”中的实际状态，并给出可采取的下一步。未启用高级功能不影响已具备能力的核心对话。

## 3. 核心用户流程

### 3.1 首次使用

打开工作台 → 在本机设置向导中准备数据目录和必要服务 → 创建本地所有者账号 → 选择已有模型目录或 API 连接 → 查看连接和能力状态 → 创建工作区 → 发起第一条任务。

已有模型权重直接引用原路径，不重复下载。模型服务可由工作台管理，也可连接用户已经启动的服务。向导明确区分“连接成功”“服务已经加载模型”和“图像或工具能力已验证”。

### 3.2 完成持续任务

选择工作区和模型 → 输入目标与附件 → 后端校验能力和权限 → 显示执行计划与任务事件 → agent 使用工具或创建子 agent → 必要时出现提问或授权卡片 → 展示产物、来源、差异和结果 → 保存任务状态与允许写入的记忆。

用户可以在执行期间补充要求、停止任务、查看已完成部分。关闭浏览器不代表取消任务。重新打开后恢复已有任务和待回答的问题。

### 3.3 更换模型

选择新连接 → 检查当前上下文、工具和附件与新模型是否兼容 → 显示转换、删去附件或另开分支等选择 → 根据用户选择继续。

不能静默丢失历史图片、改变数据传输位置，或把一次失败生成的半段内容拼到另一个模型的输出后面。

### 3.4 失败与恢复

失败发生 → 显示受影响步骤和保留的结果 → 对允许重试的瞬态故障执行有限重试 → 无法恢复时提供对应操作，例如修改配置、重新登录、选择兼容模型、重试解析、核对执行结果或取消。

用户应能理解“任务仍在运行但界面断线”“模型正在排队”“工具失败”“执行结果待核对”的区别。

## 4. 功能需求

### REQ-01 安装、启动与本地服务

提供原生安装和统一启动入口，发布包包含构建好的前端，不要求普通用户运行开发服务器。首次检查后端、数据库、数据目录和选定可选组件，明确展示需要下载的内容及用途。自动下载或安装使用默认软件源，并遵守用户操作系统权限。

允许使用现有 PostgreSQL、现有模型服务、现有权重目录。模型服务独立于前端和 API 进程，界面刷新或 API 重启不应无故重新加载模型。

**验收**：新用户按向导完成一次实际对话；缺少浏览器、OCR 或桌面组件时，具体功能显示缺失原因，核心页面仍可打开；升级不会把权重当作应用文件重复覆盖。

### REQ-02 账号、工作区与项目

首版提供一个所有者账号、多个工作区、每个工作区多个会话。工作区绑定显式允许访问的项目目录，并保存模型、工具、搜索、记忆和运行策略的默认值。

支持新建、重命名、归档工作区；移除工作区登记与删除真实项目文件必须区分。默认移除登记不删除项目内容。操作其他工作区资源必须重新经过归属检查，不能只凭资源 ID 读取。

**验收**：切换工作区后，任务、记忆、附件与配置来源正确；用户清楚数据位于哪个目录；无关路径不因模型自行构造参数而获得访问权。

### REQ-03 模型连接与模型管理

配置本地 OpenAI 兼容连接及各提供方适配器支持的远程 API；为连接设置名称、地址、模型标识、凭据、超时、并发、上下文预算和允许使用范围。兼容接口不是完整功能保证，提供方差异由适配器处理。

允许为主 agent、子 agent、文档或视觉任务选择不同模型。自动选择或故障切换只能使用用户允许的连接和数据传输范围。管理模式下提供加载、卸载、日志和准备状态；外部服务只提供其公开接口允许的操作。

**验收**：同一模型通过两个不同服务连接时可以保存不同能力和限制；凭据不回传浏览器；连接失败提供可诊断信息；远程服务不可用不造成循环重载本地模型。

### REQ-04 模型能力与多模态输入

分别配置文本、图像、音频、视频、原生文档输入，以及文本、图像、音频输出；另行配置工具调用、结构化结果和流式能力。记录模型声明、当前部署能力、用户策略和验证证据，允许未知状态。

支持附件前置校验、数量大小限制、格式表示方式限制、上下文预算检查。OCR、转写、视频抽帧、PDF 提取属于文件处理路线，不等于模型原生支持。

**验收**：文本模型收到图片时，附件仍保留，界面明确提供兼容模型或适当转换；需要读图表布局的任务不能静默改成仅 OCR 文本；切换模型时检查已有多模态历史；能力测试不偷偷调用付费 API。

### REQ-05 对话、任务与产物

支持流式对话、任务历史、运行步骤、工具日志、附件和产物预览。对话负责保存交流上下文，一次任务负责保存从接受目标到完成或停止的生命周期；一个任务可以包含多次模型和工具调用。

支持任务排队、执行中补充输入、显式停止、失败后按条件恢复、从历史创建新分支。保留原运行记录，重试和重新生成产生独立尝试记录。长输出保存为可分页读取的产物。

**验收**：重复点击发送只产生一个逻辑任务；刷新后恢复同一任务；部分输出清楚标注；用户能定位最终文件和变更，不必从整段聊天里寻找路径。

### REQ-06 子 agent 与协作

主 agent 可创建、发送消息、查询、等待和取消子 agent。每个根任务最多 3 个未释放名额，包含正在排队或等待中的子 agent，防止通过等待状态绕过限制。子 agent 不能继续创建下一层子 agent。

子任务必须携带目标、交付物、允许工具、文件范围和预算。默认只给完成任务必要的上下文。涉及同一项目的代码写入时使用独立 worktree 或串行执行，由主 agent 整合结果；子 agent 完成报告不代替主 agent 的最终验证。

**验收**：并发创建第 4 个子 agent 被明确限制或排队；取消后待进程和资源清理完成才释放名额；主任务等待子任务期间不占用模型生成槽；部分子任务失败不抹去其他已完成结果。

### REQ-07 基础工具与执行环境

提供文件查找、文本搜索、分段读取、创建和精确编辑、受控命令执行、进程输出读取与停止、任务计划、记忆访问等工具。工具统一声明输入、输出、副作用、权限、超时和取消行为。

提供工作目录受限的原生执行器，以及可选操作系统或 Docker 沙箱。界面说明实际隔离能力；不能把“限定工作目录”宣传为完整系统隔离。沙箱不可用时不静默改为主机执行。

**验收**：编辑目标已改变时返回冲突；停止任务可终止受管理子进程；超长日志不撑爆上下文；任何执行器都经过同一授权和事件链路。

### REQ-08 搜索、网页读取与来源

提供可切换 SearchProvider，优先集成 SearXNG。用户可选连接、启用引擎、语言、地区、结果数量和超时。网页读取独立于搜索，优先集成 Crawl4AI 或轻量 HTTP 读取适配器。

结果保留标题、链接、获取时间和来源；支持引用并打开原页面。提取失败允许保留搜索摘要并标注其边界。登录页、被拒访问、网络故障和解析失败分别显示，不能编造正文。

**验收**：更换搜索连接不改 agent 主流程；单个页面失败可以继续处理其他来源；离线时清楚显示网络功能不可用，本地资料检索仍可工作。

### REQ-09 多格式文件与知识资料

2026-10-18 用户反馈调整：对话附件允许所有格式直接上传，单文件最多 1 GB、每条消息最多 8 个；支持多选、拖放及粘贴，上传后自动加入草稿并准备可用内容，无需手选提取/预览/协议路线。未知格式、暂缺解析器或处理失败时保留可发送的原文件引用，明确说明内容尚未读入；不能把“已上传”当作“已理解”。复杂范围、OCR、转录、转换等保留在文件页。远程传输只保留必要的本次整批确认，受管浏览器/桌面截图及其派生内容仍只供本地模型。

支持文本、代码、Markdown、CSV/JSON、PDF、常见 Office、图像和按需启用的音视频路线。能力分为读取提取、预览、创建、定向编辑和导出，分别列出；不笼统承诺任意格式无损编辑。

文件处理保存原件、派生版本、页码/单元格/幻灯片/时间点等可获得的定位信息。提供本地资料目录和 Markdown 索引，按路径、标题、别名及正文检索，无需向量库。大量资料按需读取，不整库塞入提示词。

**验收**：处理大文件可查看进度和取消；密码、损坏、缺少解析器、部分成功分别显示；修改复杂 Office 文件默认产生可查看的副本或版本；文件内容不会未经筛选自动进入永久记忆。

### REQ-10 浏览器自动化

提供浏览器会话、页面访问、结构化观察、定位元素、点击、输入、下载和截图。优先使用页面语义与稳定定位；必要时使用截图辅助。会话配置和登录资料按工作区或用户明确隔离。

支持可视化查看步骤、接管和停止。访问外部页面产生的指令属于不可信页面内容，不能自动改写系统权限。

**验收**：目标元素失效时重新观察；不盲目重复提交表单；下载进入受控产物目录；多个 agent 操作同一浏览器会话时串行化。

### REQ-11 桌面控制

以可选 DesktopProvider 和本机伴随节点提供观察屏幕、窗口信息、鼠标键盘操作等能力。需要被控设备的授权和操作系统权限。通过浏览器访问 Spark 不等于允许控制浏览器所在的另一台电脑。

每台桌面同一时刻只允许一个自动操作写入者。支持目标设备选择、操作时间线、人工接管、紧急停止、失效截图检测。视觉模型和执行驱动均需验收，图像输入能力不等于可靠屏幕定位能力。

**验收**：在通过验收的平台完成真实应用流程；屏幕布局或缩放改变后旧坐标失效；人工接管会停止自动操作；不支持的平台明确标注，不能伪装操作成功。

### REQ-12 Markdown 记忆

提供用户级和工作区级长期记忆、小型索引及主题文件、每个任务的状态摘要。记忆可查看、编辑、删除、比较版本和恢复；每条重要记忆带来源、适用范围和更新时间。

运行中按相关性检索并加载必要内容，支持展示“本次用了哪些记忆、为什么使用”。子 agent 只提交候选记忆，由统一写入服务合并。删除记忆后更新索引、待写队列和后续上下文，防止后台任务重新写回。

**验收**：无向量库也能按中文关键词或文件路径找到明确存在的内容；工作台受管写入拒绝过期版本，检测到外部编辑冲突时保留差异并停止覆盖；需要严格保留原件时可只生成独立候选，不承诺应用内锁能阻止所有外部编辑竞态；删除后下一次调用不再使用已删除记忆；不能承诺删除记忆会自动清除原始聊天和备份。

### REQ-13 全局、项目与目录规则

工作台提供用户级全局 AGENTS.md、项目 AGENTS.md 和适用目录的 AGENTS.md。界面可查看来源和有效范围，编辑规则需明确用户意图。全局规则随用户，而不是泄漏到其他未来用户。

加载顺序与冲突处理可解释，项目及目录规则仅作用于对应范围；最新用户指令在可执行权限内生效。规则不能通过文字绕过操作系统或工具授权。

**验收**：两个项目加载各自规则；对子目录文件执行操作时使用正确局部规则；模型总结出的事实不会自动变成强制全局指令；用户撤销权限后旧提示词不能继续授予权限。

### REQ-14 提问与人工参与

agent 可以提出单选、多选或自由输入问题，显示推荐项、解释和默认选择。选择框预选不等于用户提交，等待超时不等于同意。

问题和答案持久化。用户刷新页面、切换设备或 Worker 重启后仍能回答；已失效的问题不能继续改变任务。普通澄清与操作授权采用不同语义和界面，避免把填写参数误当授权。

**验收**：同一问题在两个浏览器提交不同答案，仅一个有效版本被接受；等待时释放模型生成资源；子 agent 的问题汇总到主任务，不制造多个无法对应的弹窗。

### REQ-15 交互式与生成式界面

基础界面使用受控 React 组件展示问题、计划、任务树、差异、文件、模型状态和真实指标。支持通过版本化适配器接入 AG-UI 事件与 A2UI 可信组件描述。

将自由生成的 HTML/CSS/JavaScript 作为隔离渲染能力，限制宿主调用接口、网络和可访问数据。生成内容中的按钮不能直接获得后台权限。普通设置和授权流程不依赖模型临时生成代码。

**验收**：不合法组件描述降级为可读文本或表单；无真实数据时显示空状态；恶意生成内容无法读取其他工作区凭据；刷新后问题和关键任务状态仍由后端恢复。

### REQ-16 缓存与上下文效率

提供稳定提示词前缀、工具集合快照、适度上下文压缩、可配置的提供方缓存策略。区分模型前缀缓存、只读工具结果缓存和完整回答缓存；完整回答缓存默认关闭。

对话输入区显示最近模型请求的上下文占比，展开可见计数来源、窗口、剩余空间、更新时间和压缩前后用量；未知和估算不得展示为精确实测。支持手动压缩及按预算自动压缩，摘要跨后续任务持久复用，原始消息保留并可按消息及字符游标恢复。仅在摘要完整生成、来源及新要求复核通过后发布；取消、失败、记忆遗忘或接收方变化不得继续使用失效摘要。未发送草稿不计入最近请求占用。

支持查看缓存读取、写入、命中口径和统计覆盖率。优化缓存不能牺牲最新指令、已撤销权限、模型兼容性或答案正确性。

**验收**：相同稳定前缀不会因无关时间戳或工具顺序变化失效；提供方不返回命中统计时显示未知；缓存写入不算读取命中；不同权限范围的数据不会误用同一工具缓存。

### REQ-17 数据看板与可观测性

提供按时间、模型连接、工作区和任务筛选的真实数据：请求数、成功失败、首响应/首段可见输出时间、排队时间、输出速率、输入输出 tokens、缓存、费用或估算、工具耗时、子 agent 活跃数量和可获得的硬件资源指标。

记录每次重试的消耗，区分模型提供方报告与本地估算。图表应显示单位、样本数、时间范围及缺失数据；不能把未知填成 0。

**验收**：能从图表追溯到任务和调用；停止或失败的请求保留已知用量；同一调用不会因 SSE 重连重复计费；Spark 统一内存不能把同一块内存重复相加展示。

### REQ-18 全系统失败恢复

覆盖模型、工具、文件解析、搜索、数据库、Worker、前端连接、桌面驱动和遥测故障。统一错误分类与有限重试，但不同模块采用符合副作用的恢复方式。

执行结果不确定时进入核对流程；有副作用的操作不能因连接超时直接重做。保留已完成步骤、文件与输出，明确支持恢复的检查点边界。系统不能承诺对任意外部操作实现严格一次执行。

**验收**：网络短暂中断不造成无限重试；Worker 重启能恢复可恢复任务；数据库不可写时停止新的不可追踪副作用；日志上传失败不会重放成功工具；取消后不自动复活任务。

### REQ-19 权限、隐私与安全边界

默认仅监听本机；局域网访问显式开启并要求认证与安全会话配置。用户管理可访问目录、网络、设备、模型连接和工具。密钥由后端安全存储，前端只显示脱敏状态。

外部模型切换、文件和截图上传遵守用户配置的数据边界。每次执行重新检查当前权限，而非只在任务开始时检查。网页、附件、MCP 返回的文字均不得自行授予权限。

**验收**：伪造资源 ID 不能跨工作区取数据；被撤销的工具授权即时阻止后续调用；生成式界面和子 agent 不能扩大父任务权限；导出诊断包默认脱敏。

### REQ-20 扩展接口与开源复用

为模型、搜索、解析器、浏览器、桌面、沙箱和 MCP 提供稳定适配接口。插件声明版本、所需能力、配置 schema 和健康状态；缺少一个扩展不导致所有模块启动失败。

首版扩展优先采用受管理的内置适配器和配置化 MCP 连接，不开放自动下载安装并运行任意第三方插件的公共市场。

**验收**：增加搜索或模型连接不需改动会话状态机；适配器返回统一错误和来源信息；插件内部私有字段不会直接成为数据库通用字段；许可证不兼容的商业功能不混入默认开源链路。

### REQ-21 配置与可调节性

设置按应用、用户、工作区、任务四级组织；显示当前值、来源、作用范围和生效时机。常用项提供表单，复杂配置支持带校验的高级编辑和恢复默认。

至少包含：模型和能力、主/子模型选择、子 agent 上限、模型并发、上下文预算、搜索引擎、工具和沙箱、文件处理路线、记忆策略、权限、缓存、重试、任务预算、日志保留和数据目录。

**验收**：错误配置无法悄悄保存为可用；运行中修改设置时说明哪些下次任务生效，哪些需要重新连接或立即收紧；不得通过任务参数突破用户权限或硬件硬限制。

### REQ-22 数据生命周期、导出与维护

支持导出会话、任务摘要、产物和 Markdown 记忆；支持一致性备份与恢复、数据库迁移、磁盘占用说明和按类别清理。任务状态、原始文件、派生文件和统计按明确保留策略处理。

备份区分可重建索引和不可替代的原始数据；大型模型权重独立管理。升级前检查版本兼容和必要备份，失败时说明可回退范围，不能假定任意数据库迁移都可逆。

**验收**：从备份恢复一个包含附件、记忆和待回答问题的工作区；清理缓存不删除唯一原件；模型目录可以被外部引用而不随应用卸载被自动删除。

## 5. 用户界面要求

主要导航包括工作区、对话与任务、文件与产物、记忆与规则、模型与连接、工具与设备、数据看板、设置。普通用户首先看到当前目标、进展、需要处理的事项和最终产物；调试字段放在详情中。

任务主界面应提供对话区、可收起的任务/子 agent 面板、产物与差异面板。窄屏可逐页切换，不能要求用户同时看三个面板才能完成任务。工具调用和错误不能只以短暂通知出现，应在任务中保留可定位的记录。

键盘可完成发送、选择、提交问题、查看错误和停止任务；按钮状态和错误不能只靠颜色表达；长日志可滚动、复制和下载，界面不被未截断的输出撑死。

## 6. 非功能需求与约束

### 6.1 正确性和持久性

数据库是任务生命周期的事实源，Markdown 是用户可读长期记忆的内容源，原始文件是产物派生链的源头。三者通过明确记录和恢复机制衔接，不假设跨数据库和文件系统天然具有一个事务。

任务必须有终止条件、预算、取消链路和可解释状态。所有外部副作用说明重试与结果核对方式。

### 6.2 性能和资源

模型加载、上下文长度、缓存、OCR、ASR、视频和子 agent 共享资源。优先保证正在交互的任务，后台整理和批处理有独立限额。不能根据权重文件大小直接承诺实际运行内存或并发能力。

性能目标根据实测确定，至少区分首次响应、可见输出、请求时延、队列等待、资源峰值及取消响应。已有固定模型的加载、32K 配置运行、工具和图像流程，以及一次受控冷/热前缀缓存测量；这些不是完整压力基准或持续服务等级承诺。看板使用真实请求与硬件数据，缺失项保持未知。

### 6.3 维护性与兼容性

内部契约版本化，模块通过公开接口交互；不跨模块直接改私有表。依赖锁定并保留适配器契约测试。配置、数据 schema、事件和插件协议升级有兼容策略。

“企业级长期维护”落实在边界、数据迁移、故障恢复、访问控制、可观测性和发布过程，不作为引入 Kubernetes、微服务或额外数据库的理由。

### 6.4 离线能力

已有模型、必要运行依赖和本地文件齐备时，核心任务可离线运行。搜索、外部 API 和新资源下载明确标记需要网络。首次安装、首次下载解析模型与每次处理文档是否联网必须分开说明。

| 项目 | 本版默认设计 | 变化规则 |
| --- | --- | --- |
