# 模型接入、上下文、Markdown 记忆与数据看板

本章覆盖模型能力、请求编译、缓存、记忆和计量；运行标识及事件服从[运行时契约](runtime-and-data.md)。配置概念属于工作台内部契约，不可直接当作提供方原生字段发送。实际字段以 DTO/OpenAPI 为准；已实现与实机验证范围见[状态清单](../implementation-status.md)。

1.0.0 当前实现：固定本地`Qwen3.8-Flash-Next-NVFP4`使用131072上下文、MTP和单推理许可；模型连接、思考预设、持久语义压缩、记忆与真实用量看板已有实现及本机证据。当前AI操作见[说明书](../ai-guide.md)，最新历史读取和接口边界见[状态第22节](../implementation-status.md#22-2026-10-26-跨对话读取与-ai-操作说明)。下文S0顺序保留最初验证方法，不表示当前仍停留在模型资产/设计阶段；其他平台、原生视频及外部提供方按状态清单保留各自限制。

## 1. 模型连接与部署对象

不能只用模型名称判断可用能力。一个模型经不同量化版本、推理引擎、API 适配器和服务配置部署后，可能暴露不同输入格式、工具协议和限制。

将信息分成四个对象：

1. **ModelDefinition**：模型标识、权重来源、模型族和公开声明。
2. **ModelConnection**：用户实际连接的地址、提供方协议、模型名、凭据引用与允许范围。
3. **DeploymentRevision**：引擎、权重修订、模板/解析器、关键启动配置的版本或可获得指纹。
4. **ModelCapabilityProfile**：针对该连接和部署版本的有效能力、用户策略及验证证据。

外部 API 可能不公开权重修订或引擎，此时记录未知及可获得的服务版本，不伪造部署指纹。连接地址、模型标识或关键配置发生变化时，受影响的验证结果失效；不能把旧测试当新部署的证据。

### 1.1 连接配置

包含 connection_id、名称、provider_type、endpoint、model_identifier、credential_ref、managed/external 模式、protocol_version、超时、生成并发、上下文预算、可用工作区、允许的数据类别和降级候选。

OpenAI 兼容端点作为一种适配器，不意味着支持所有 OpenAI 特性。Anthropic 等其他协议使用独立适配器；提供方特有字段只能在经过 schema 校验的扩展配置中保存，不能随意透传任意请求体。

### 1.2 服务管理状态

受管理本地服务显示 stopped、starting、loading、ready、degraded、stopping、failed 等服务状态。这是模型服务生命周期，不复用 Run 状态枚举。

外部连接只显示连接检查与实际请求观察到的状态，不能声称可控制其加载或进程。探测连接与实际推理分开：列表接口成功不代表图像、工具、结构化输出已经通过验证。

## 2. 能力模型

### 2.1 三层能力与独立证据

- **声明能力**：官方模型资料或用户填写的预期能力。
- **部署能力**：实际端点、引擎、模板和适配器能接受并正确处理的能力。
- **用户策略**：允许在当前用户/工作区/任务中使用哪些能力，尤其是文件、截图和远程传输。

每个能力项有 support = supported / unsupported / unknown，evidence_status = declared / manually_asserted / verified / verification_failed / stale，evidence_source、checked_at 和 deployment_revision。支持状态与证据状态不能合并成一个勾选框。

用户可以补充声明、禁用能力和选择转换路线；不能通过一个“支持图片”开关把明确不支持图片的适配器变成视觉服务。手动允许使用尚未验证的能力时，显示“用户声明，待验证”，执行前仍做格式和硬限制校验。

### 2.2 能力字段分组

| 分组 | 必须分别表示的内容 |
| --- | --- |
| 输入 | text、image、audio、video、native_document；PDF 等作为文档子类型 |
| 输出 | text、image、audio、video；支持读取图像不等于生成图像 |
| 表示方式 | 文本块、内联编码、远程 URL、提供方文件 ID、帧序列等 |
| 消息位置 | 用户消息附件、工具结果中的图像/文档能否使用 |
| 工具 | native tool calling、指定工具选择、多个工具调用、工具参数流式输出 |
| 结构化输出 | JSON 模式、schema 约束、严格校验分别表示 |
| 流式 | 文本、工具参数、用量尾事件、可否按提供方机制续传 |
| 限额 | MIME、单文件大小、数量、图片分辨率、媒体时长、输入/输出 token 上限 |
| 推理控制 | 是否允许关闭或调节推理、可用控制项，均按当前部署填写 |
| 电脑任务 | 视觉输入、工具调用、屏幕定位验证情况；不能仅凭 model_type 自动推导可靠性 |

未知上限使用 null/unknown，不填 0。零表示明确禁止或实际为零；两者在前端和统计中必须区分。

### 2.3 能力来源与元数据复用

可以从 models.dev、LangChain Model Profiles 或用户保存的离线目录导入初始元数据，再叠加部署证据。模型列表缺失时仍允许用户添加自定义连接。

LangChain 的 profile 仍可能有字段缺失和格式演进，项目应使用自己的稳定 schema，通过适配器导入，不直接把上游字典作为数据库公共结构。同一公开模型被不同提供方部署时，提供方覆盖值优先于通用声明，但仍需实际连接验证。[LangChain Model Profiles](https://docs.langchain.com/oss/python/langchain/models#model-profiles)、[models.dev](https://github.com/anomalyco/models.dev)。

### 2.4 输入预检流程

1. 确认任务实际需要什么信息：文本内容、版面、视觉细节、声音或时间序列。
2. 解析附件真实类型、大小和归属，不能只信扩展名或前端 MIME。
3. 核对当前连接的原生能力、表示方式及上下文限制。
4. 不匹配时提供可用路线：兼容模型、明确转换、保留附件等待处理，或用户移除。
5. 转换计划说明信息损失与联网位置，再由 FileProcessor 生成派生版本。
6. 编译请求前再次检查当前策略、转换结果和模型连接版本。

例如 OCR 可以把扫描文字交给文本模型，但不保证保留图表颜色和布局；ASR 转写不能完整保留说话人语气；抽取视频关键帧不等于理解全部连续动作。不能用静默转换假称原任务信息完整。

检查适用于主 agent、子 agent、自动选择、故障降级和历史恢复。更换模型后应重新检查历史附件和工具结果，而不仅是最新一条用户消息。

## 3. 内部消息与提供方适配

### 3.1 CanonicalModelRequest

统一请求包含：模型连接与部署版本、run/step/attempt 标识、编译后的消息、工具 schema 快照、生成参数、输出约束、缓存策略、预算和取消句柄。

内部消息采用显式内容块：text、image_ref、audio_ref、video_ref、document_ref、tool_call、tool_result。附件块引用受控 artifact/version，不直接携带模型随意指定的主机路径。每个引用带来源、用途和转换关系。

System、developer、user、assistant 和工具结果的表达由适配器按提供方实际协议编译；不能把不支持的角色直接原样传过去。需要转换时保持指令与不可信资料的边界，不把附件中的命令提升为系统规则。

### 3.2 模型输出的处理

ModelProvider 输出统一事件：开始、文本片段、工具参数片段、完整工具调用、用量、结束原因和错误。只有完整收集、JSON 解析及 schema 校验完成后才可执行工具；流式字符串出现了一个文件路径不构成执行许可。

工具名字、参数和调用 ID 经过白名单及映射检查。错误参数作为模型修正机会还是终止错误，由 ToolExecutor 和总预算决定；语义修正与网络重试分开计数。

动态工具默认增量加载。同一对话的后续 Run 从选定历史中已完成、与 assistant 发现调用 ID 配对的真实 `loaded` 回执恢复工具集合，避免历史说“已加载”而新请求重置为核心工具。分支只继承锚点内的历史，显式集合及卸载结果保持；注册目录、子任务允许工具、搜索开关和操作审批仍在当前边界核对。

提供方输出的可见推理或协议要求的 opaque 数据按能力和数据策略处理，不假称能取得隐藏推理。向用户展示的步骤说明应是可验证的动作和结果；不以生成一段“思考日志”代替执行证据。

### 3.3 API 差异与降级

工具并行开关、严格结构化输出、缓存参数、思考控制、文件上传和重试语义不能仅靠模型名猜测。适配器声明支持范围，调用前拒绝不支持的必需参数；可以省略的可选参数才按显式规则降级。

当前生成配置将 `provider_type` 与 `engine_kind` 分开：前者决定 Chat、Responses、Anthropic 等消息协议，后者标记 `auto`、`sglang`、`vllm`、`llama_cpp`、`tensorrt_llm` 或 `other`。列出引擎类型不代表其所有扩展都已适配或实机验证。`auto` 只对与受管部署地址、模型名相符的回环连接识别引擎，并兼容旧本地 SGLang 观测配置；远程地址不据此猜测引擎。

思考模式默认沿用服务模板，也可显式启用或关闭；当前非默认参数映射限于 SGLang/vLLM 的 Qwen3 系 Chat 路线，名称含 `thinking` 的固定思考模型不使用该开关映射。Qwen3.8 强度映射为 `low`、`medium`、`xhigh`，不接受通用枚举中的 `high`。关闭思考不能同时指定强度，未知协议、引擎或模型组合会明确拒绝非默认设置。请求的模板参数同时用于输入计数；可读思考展示与生成控制分开，工作台不保证取得隐藏推理。具体实现见 [engine_adapters.py](../../apps/server/src/workbench/modules/models/engine_adapters.py)。

自动切换模型先检查：能力是否满足原目标、工具协议能否重编译、数据能否送往新位置、费用和预算是否允许、已经完成的工具结果是否可安全复用。部分模型输出保留为原 attempt 的未完成内容，不与新模型输出伪装成一次连续生成。

云端文件 API 的上传和保留策略是独立操作。用户选择远程模型不代表所有历史文件都可永久上传；按任务所需最少内容、允许范围和提供方机制处理，并保留上传引用及可执行的清理状态。

## 4. 当前 Spark 模型的接入规格

现有资产为 `models/nvidia/Qwen3.8-Flash-Next-NVFP4`，此前下载并校验的固定修订为 `fc694b54fb0174e0913e6adf86691ef85a4ead47`。25 个文件共 132,734,506,847 字节，包含 11 个权重分片和 14 个其他文件。此处记录已有下载证据，不再次执行权重哈希检查。

配置包含 `Qwen4ExpForConditionalGeneration`、vision_config、image_token_id 和 video_token_id，说明模型配置声明了视觉相关结构。它不能证明当前推理服务已经正确接通图像或视频输入。

在单台 Spark 上，file-backed PLE、NVMe 访问、适配该混合 NVFP4 格式的引擎/加载器和算子组合是关键条件。CPU pinned offload 仍占统一内存，不会凭空增加另一份显存。部署章节列出版本与平台验证门槛，本文不提供未经执行的“一定可用”启动命令。

S0 原始最小验证顺序（历史实施方法）：

1. 权重读取与服务准备状态，测量加载过程和稳定内存。
2. 普通文本、流式结束原因、实际用量和取消。
3. 一个只读工具和一个受控文件编辑工具的完整调用与结果回传。
4. 图片输入与实际理解验证；视频路线单独检查表示方式和处理器。
5. 相同前缀的多次请求与缓存统计，观察实际命中和延迟。
6. 一个主任务加子任务排队，验证共享模型资源；并发从 1 开始，再决定是否提高。

最初先建立不启用 MTP 的正确性和资源基线，随后已按用户要求开启 MTP 并完成128K真实长输入及后续工作台流程；历史非MTP测量保留原参数，不能改写成当前部署的基准。文件体积不等于运行内存，图像能力不等于电脑定位能力，模型宣传上下文长度不等于本机可承受长度。

## 5. PromptCompiler 与上下文预算

### 5.1 编译输入和顺序

PromptCompiler 接收规则快照、任务目标、历史、相关记忆、附件派生引用、工具集合及提供方能力，输出可发送请求和可解释的编译清单。

推荐组织：稳定系统规范 → 用户全局与项目规则 → 稳定角色/工具定义 → 本次选择的稳定记忆摘要 → 按时间追加的对话、任务输入和工具结果。具体序列按提供方缓存和协议调整；不得为固定顺序破坏其合法消息格式。

每次编译记录使用的规则文件及版本、记忆条目、工具集合版本、附件转换、压缩摘要和估算 token。完整敏感提示词不默认进入普通日志，但用户可在受权限保护的诊断视图查看实际发送范围。

### 5.2 预算算法

有效输入预算 = 当前部署允许的上下文容量 − 输出预留 − 协议/媒体开销预留。模型连接中的窗口必须与服务实际启动上限相容；模型配置声明的最大长度、单请求服务上限和引擎 token 内存池容量分别核对，不能互相代替。任务使用接受时冻结的连接窗口，不能仅提高界面数字就认为服务容量已增加。

当前文本 Chat 请求在本机回环 SGLang 路线上，通过同一提供方请求转换取得实际 `messages`、`tools`、`chat_template_kwargs` 和 `reasoning_effort`，发送到该服务的 `/v1/tokenize` 计数。计数复用生成使用的 Chat 模板和工具表示，不另外拼接一份近似提示词。其他引擎或协议、含原生媒体的输入，以及分词接口超时、响应无效或不可用时，回退到 UTF-8 字节数除以 2 加附件预留的估算，并标记 `estimated`；分词计数标记 `tokenizer`。估算不能作为匹配 tokenizer 的精确结果，也不作为提供方结算用量。

输出上限为 `null` 时采用自动额度：`当前总窗口 − 编译输入计数 − 保留媒体预留 − 256 token 协议余量`。自动压缩规划先预留 `min(8192, 窗口 / 4)`，压缩后重新编译和计数，再把实际剩余空间交给生成；8192 是规划预留，不是自动输出的固定上限。用户显式设置输出额度时保留该限制，压缩触发预算也使用该额度。最终额度不足 64 token，或显式额度超过剩余空间时暂停并说明预算不足。媒体预留随最终保留的消息重新计算，不继续扣除已由摘要替代的附件。

预算不足时按顺序处理：裁剪可重新读取的长日志预览 → 延迟加载低相关资料 → 选择相关文件区段 → 对已完成且可独立引用的历史段生成摘要 → 仍不足则请求调整范围或切换兼容配置。最新目标、权限变化和未配对的工具调用/结果不能被随意移除。

不要把某个提供方的 tokenizer 用于所有模型并展示为精确计费。输入预算、输出上限、推理开销和实际 token 记录需区分。

### 5.3 压缩与上下文恢复

保留原始事件和消息；压缩结果是带版本的派生上下文，不覆盖原始证据。压缩只在完整工具边界进行，工具调用及结果成对保留，未完成问题和操作引用必须可恢复。

迁移 `033_thread_context` 增加每个 Thread 独立的 `thread_contexts` 持久状态，记录活动语义摘要、版本、覆盖消息计数、摘要全部来源依赖、记忆指纹、接收方范围、用量观测和压缩请求状态。摘要可跨同一对话的后续 Run 复用；新请求仍先从原消息重建并过滤当前权限、记忆与来源，再核对摘要依赖，不能凭旧摘要绕过新限制。重复的相同消息按指纹计数，既不把后续重复消息一并移除，也不把少了一次来源当作依赖齐全。

自动压缩默认在编译输入超过“窗口减输出预留”的 90% 时触发，`context_target_ratio` 可按运行选项调整；这里的 90% 是输入预算占比，不是总窗口的固定占比。压缩保留最新真实用户要求、尚未送达的输入及最近完整工具组，其他历史按有界尾部选择，避免压后立即回填到触发线上方。`runtime_continuation`、运行提醒和旧摘要有独立来源标记，不当作最新用户目标。

手动压缩通过聊天中的“手动压缩”以及 `POST /api/v1/threads/{thread_id}/context/compact` 提交幂等请求。进行中的任务在下一次生成安全边界处理；空闲或等待中的对话使用不列入普通任务列表的 `context_compaction` 后台 Run，仍共用模型准入容量。新用户任务优先接管空闲压缩请求，已开始工具不因压缩重放。请求状态和原摘要均持久保存；工作器恢复时核对同一请求并收束旧摘要 Attempt，不能以重复点击或进程恢复产生多个活动摘要。

语义摘要使用该任务选定连接的真实模型生成，输入为历史文本与已有摘要，不提供可执行工具，不发送图像二进制或隐藏推理。摘要提示要求保留完整目标、最新约束、已确认决定、产物位置、必要证据、剩余工作、阻塞和下一步，并区分已实现、辅助检查与真实验收。超出一次压缩空间时按完整消息/工具组分批，前一批摘要带入后一批；每一批都携带当前真实用户目标，优先保留该问题所需的具体数值与来源，避免首批不知道后续问题而过早丢失资料。单组接近窗口时按实际剩余空间安排摘要生成额度，正常请求输出额度不受此摘要额度限制；完整组及当前目标仍放不下时明确失败，不静默截断。模型生成的语义摘要仍可能有遗漏，原始记录是恢复和核对依据。

`STATE.md` 作为派生产物发布，标记语义摘要及来源依赖；旧的事实索引产物和原消息继续保留。只有模型正常完整结束、返回非空纯文本、候选上下文更小、产物发布成功，且提交时摘要版本、请求、记忆与接收方范围仍匹配，才原子替换活动摘要。新 Steer 在提交前检查并触发重新编译；取消、截断、失败或工作器失去执行所有权时不将半成品切换为活动摘要。摘要依赖覆盖它读过的全部来源，包括保留尾部，并在后续压缩中继续继承；记忆遗忘、来源变化或切换到不同远程接收方会使旧摘要失效。摘要文件读取和历史片段恢复也保留记忆来源检查，不能借读旧 STATE 恢复已遗忘正文。

运行恢复先从持久状态和摘要继续，只有记录缺失、版本变化或证据冲突时补读相关文件，不重新全量调查。上下文压缩与缓存优化发生冲突时，以任务正确性和可恢复性为先。

`read_task_history` 可先按 `start_message` 分页取得消息 ID，再以 `message_id` 和从 0 开始的 `start_character` 读取同一条长消息的后续正文。响应给出 `next_character`、`total_characters` 和 `truncated`；继续读取时使用返回的字符游标，不能把首段当作完整原文。当前默认每条 4000 字符，可请求至 65536 字符，仍受当前任务树、授权对话历史、记忆遗忘和附件接收方过滤约束。工具结构和实现见 [registry.py](../../apps/server/src/workbench/modules/tools/registry.py) 与 [extensions.py](../../apps/server/src/workbench/modules/tools/extensions.py)。

`list_conversations`、`search_conversations`、`read_conversation`已补充独立对话目录、实际关键词定位及消息/字符续读。默认当前用户当前工作区，用户可关闭或明确允许账户内跨工作区；子agent仍限当前任务树。范围变更、消息/来源变化、记忆遗忘及文件传输限制均在后续上下文再次检查，失效片段不继续注入，依赖旧片段的摘要也不可复用。读取不会启动原任务、自动读取图像或扩大文件路径权限；设置和实际操作见[AI说明书](../ai-guide.md)。

### 5.4 聊天上下文占用

`GET /api/v1/threads/{thread_id}/context` 提供已用、窗口、剩余、来源、更新时间、压缩状态及最近压缩前后计数。聊天输入区显示占比并可展开这些明细。该指标基于最近一次编译/请求：生成前显示分词计数或估算；正常请求取得完整用量后，以提供方输入加输出更新为 `measured`。旧对话没有新状态行时可只读回查最近正常生成的已知用量；无可用记录时保持未知。

指标不随尚未发送的草稿实时计数，也不是对话累计 token 消耗或下一次请求额度承诺；界面上的更新时间用于区分最近观测和当前输入。改变模型后不沿用另一连接的占用数值。缓存读取仍占请求上下文，不从已用窗口中扣除。活动语义摘要的计数变化与其模型生成成本分别记录，不能把压缩请求的 token 用量当作压后上下文大小。

以上描述当前实现路径；迁移部署、模型生成质量、长上下文容量及界面流程的真实验证结果分别见部署证据与[状态清单](../implementation-status.md)，不能用纯函数测试或代码接线替代。

## 6. 缓存设计

### 6.1 缓存带来的实际收益

模型前缀缓存可减少重复输入的预处理，提高首响应速度和吞吐，降低服务负载，并有助于在相同硬件上容纳更多排队工作。外部 API 还可能提供输入折扣。实际收益取决于提供方、缓存保留、匹配条件和当前瓶颈；不能承诺命中就一定加快每个输出 token。

本地缓存仍占内存，缓存过多可能挤压可用并发或长上下文。目标是任务时延、成功率、费用和资源平衡，而不是追求一个孤立的命中率。

### 6.2 三种缓存分开

| 缓存 | 缓存对象 | 本版策略 |
| --- | --- | --- |
| 模型前缀缓存 | 重复前缀的推理状态 | 优先优化，按引擎/提供方适配 |
| 只读工具缓存 | 搜索、网页或其他可缓存读取结果 | 根据权限、参数、版本和时效精确作用域化 |
| 完整回答缓存 | 整次用户问答结果 | 默认关闭，不作为通用任务的替代执行方式 |

修改文件、发消息、点击提交和执行任意命令的结果不能按“文字看起来一样”直接缓存复用。工具缓存的调用成功不代表来源仍最新，应显示获取时间和过期规则。

### 6.3 提高前缀命中的具体措施

1. 固定系统规范、角色说明和工具排序，采用稳定序列化；不在头部加入每次变化的时间、随机 ID 或实时硬件状态。
2. 使用按任务类型选择的小型工具集合，在运行安全边界才改变工具定义；工具版本和顺序都属于快照。
3. 固定本次任务的规则和记忆基础快照，新发现作为增量追加；重要用户修改和权限撤销立即进入有效上下文。
4. 同一对话保留可合法追加的前缀，避免每轮把所有历史重新摘要或重新排序。
5. 提供方支持显式缓存断点、缓存键、保留期限或会话亲和时按其规则设置；不支持时不发送虚构参数。
6. 模型连接切换、模板变化、图像表示变化和工具 schema 变化单独记录为可能的失效原因。
7. 本地引擎缓存配置在实际模型上验证。混合架构的缓存不一定只是普通 Transformer KV，不能按 NVFP4 权重量化推断缓存也为 4 bit。

不为提高命中率加入无用长前缀、隐藏付费预热请求、无限延长过期数据或忽略用户最新要求。缓存键中包含必要归属和权限版本，避免共享读缓存跨越数据边界。

### 6.4 工具缓存键与失效

键包含工具 ID/版本、规范化参数、用户/工作区范围、凭据或权限修订、来源版本和转换设置。网络内容按来源策略设置时效，项目文件按明确内容版本失效，权限撤销立即禁止旧结果访问。

参数摘要可以用于键，但原始密钥不得出现在键、日志或监控标签里。查询参数包含敏感信息时，缓存本身也按数据权限存储。

## 7. Markdown 记忆与规则

### 7.1 四类记录，四种责任

| 类型 | 用途 | 内容所有权 |
| --- | --- | --- |
| AGENTS.md | 用户要求 agent 遵循的规则 | 用户明确编辑或授权修改 |
| MEMORY.md + 主题文件 | 稳定偏好、项目知识、可复用事实 | 记忆服务受控维护，用户可编辑 |
| STATE.md | 当前任务目标、进展、证据与下一步的可读派生记录 | Run 发布产物，活动语义摘要另存于 ThreadContext |
| LangGraph checkpoint / 消息与操作记录 | 精确恢复执行、核对步骤及副作用 | 运行时数据库 |

AGENTS.md 不能被当作“模型想到什么就追加什么”的笔记本；STATE.md 也不能替代工具执行幂等记录。

### 7.2 目录设计

```text
<工作台数据目录>/
  users/<user_id>/
    AGENTS.md                         用户级全局规则
    memory/
      MEMORY.md                       小型索引
      preferences.md                  用户允许保存的稳定偏好
      topics/                         按主题保存的事实
  workspaces/<workspace_id>/
    memory/
      MEMORY.md
      topics/
    runs/<run_id>/STATE.md             当前任务摘要
    artifacts/                        原件和派生文件
    staging/                          尚未发布的临时版本

<用户项目目录>/
  AGENTS.md                           项目规则
  backend/AGENTS.md                   适用目录规则（如用户提供）
  docs/knowledge/...                  用户明确选择公开到项目的资料
```

这是逻辑目录说明。当前已实现用户级 `users/<user_id>/AGENTS.md`、按用户/工作区分隔的记忆文件及索引、独立修订和任务摘要；主题文件采用受管文档标识命名，具体路径由服务生成，不要求存在示意中的 preferences.md。项目记忆默认保存在工作台私有数据目录；只有用户明确发布时才写入项目可提交文件，避免私人偏好和任务日志误入 Git。

### 7.3 规则加载与冲突

用户级全局规则先提供通用要求，项目规则补充项目约定，相关目录规则细化该路径范围。目录规则只作用于目标目录及其子树，不因读到一个文件就污染整个工作区。

新的明确用户指令可以改变任务目标和偏好，但不能绕过操作系统、账号或工具实际权限。网页、附件、工具日志中出现的“AGENTS.md”文字不自动成为规则；规则来源必须是登记范围内的真实文件或用户设置。

每次编译保留文件路径、版本、作用范围和冲突处理说明。用户修改关键规则后在下一安全边界重编译；权限撤销由独立 Policy 立即约束，不依赖模型是否读懂文字。

### 7.4 记忆内容格式

每个主题文件保存可编辑正文与少量稳定元信息：文档 ID、范围、来源引用、更新时间、适用项目/分支/版本和有效性。需要逐条遗忘或追溯的条目有稳定 entry_id，不依靠文本相似度猜测它是不是同一条记忆。

元信息可采用经过 schema 校验的 YAML front matter 和条目 ID；其余正文仍是普通 Markdown。Markdown 解析器和 schema 版本明确，不能把用户任意 YAML 标签解释成可执行对象。

信息分为用户明确要求、来源可验证事实、待验证推断。涉及经常变化的版本、环境和部署事实写明适用范围，并在需要时重新核对。长期记忆不收集无关隐私，也不自动保存密钥。

### 7.5 无向量检索流程

先按用户/工作区/项目范围筛选 → 读小型 MEMORY.md 索引 → 根据文件名、标题、标签、别名和中文子串/关键词检索 → 返回带来源和定位的短片段 → 按需读原文。

初版使用受限路径遍历与 `rg`/等价原生检索，程序调用传递参数数组，不把查询拼成 shell。索引和路径限制必须避免读取授权范围外文件。

可选全文索引属于可重建派生数据，不是向量库。以后选择具体引擎时需验证中文分词及短词行为，不把英文 tokenizer 的效果直接当中文能力保证。跨文档语义关联弱于向量检索时可让 agent 做多轮关键词扩展，但不承诺两者效果完全相同。

### 7.6 写入、合并与并发

运行内产生的候选进入 memory_proposals，携带来源、建议范围、冲突情况和原版本。子 agent 只提交候选；统一 MemoryWriteService 去重、核对和合并。

写入使用预期版本 + 文档锁 + 临时文件 + 原子替换 + journal。受管并发写入拒绝过期版本；检测到外部编辑时暂停合并，保留基础、当前可读版本和候选差异。外部编辑器不受应用内锁控制，不能承诺捕获所有同时写入；需要严格保留原件时只生成独立候选，写回时机由用户决定。具体保证与限制统一见[文件与数据库一致性](runtime-and-data.md#7-文件与数据库之间的一致性)。

默认在步骤或任务完成后的合适时机整理，受后台资源预算控制。记忆整理所用模型调用也记录用量；不能为了节省前台 token 在后台无限花费。

### 7.7 遗忘与恢复

删除条目时更新正文和索引，写 tombstone，取消或标记相关候选，失效后续检索与工具缓存。运行中的上下文已包含该条目时，在下一次模型请求前重建有效上下文，避免继续发送被删除内容。

遗忘不等于撤回已经发给外部 API 的内容。原始聊天、文件、备份是否保留有独立操作；界面必须说明。恢复已删除版本属于显式用户行为，旧备份恢复后仍需核对遗忘屏障，避免静默复活内容。

## 8. 用量与数据看板

### 8.1 计量记录

UsageNormalizer 接收提供方原始用量、当前模型/价格修订、attempt 标识和测量时间，将可确认字段归一化，同时保留来源和 unknown 状态。

至少记录：input_tokens_total、output_tokens_total、cache_read_input_tokens、cache_write_input_tokens、reasoning_tokens（若提供）、请求和首事件时间、首段可见文本时间、结束时间、终止原因、价格币种与版本、计量来源和已知覆盖情况。

提供方对 input_tokens 是否包含缓存读取/写入、output_tokens 是否包含 reasoning 的口径不同。适配器必须根据官方定义映射；不能把子集再次相加，也不能把缺失字段当 0。无法确认总量时保留未知，而不是用不完整字段制造精确总数。

语义压缩的每批真实生成都有独立 Step、Attempt 与 UsageRecord，`purpose=context_compaction`；成功、失败、引导中断和取消均保留实际可得用量，提供方未返回时为未知。STATE 的发布不是一次零成本文本裁剪，也不以摘要字符数伪造该次模型用量。压缩前后上下文大小另存为 `before_tokens`、`after_tokens` 及计数来源，分词/估算与提供方实测分别解释。

### 8.2 缓存指标

**输入 token 命中率**：在“输入总量和缓存读取量均已知且口径可比”的请求集合内，sum(cache_read_input_tokens) / sum(input_tokens_total)。分母为 0 时显示无可计算样本。不能先计算每个请求比例再无权平均。

**请求命中率**：同一已知集合中，缓存读取量大于 0 的请求数 / 可判断请求数。它回答“有多少请求碰到了缓存”，与 token 命中率回答的问题不同。

**统计覆盖率**：可判断缓存的请求数 / 应纳入统计的请求数，必要时另报输入 token 口径的覆盖范围。看板把命中率和覆盖率并排显示；部分提供方不返回统计时，不把整体命中率写成全部请求的结论。

缓存创建/写入是不同计量项，不算读取命中。统计默认可包含失败请求的已知用量，并可按终止状态筛选；筛选条件清楚显示。

### 8.3 速度与时延

- 提交至开始执行：任务排队时间。
- 等待模型许可：模型排队时间，不包含在引擎纯解码速度中。
- 请求发出至首个提供方输出事件：API 首输出时间，需注明可能是推理或工具事件。
- 请求发出至首段用户可见回答：可见首响应时间，更贴近对话体验。
- 完整任务时长：包含工具、等待和恢复，可拆分，不能只用某一次模型请求代替。
- 引擎报告的解码 tokens/s：只有实际提供且口径明确时展示为引擎指标。
- API 请求平均输出速率：已知 output_tokens_total / 该请求持续时间，明确它包含请求阶段开销。
- 可见文本生成速率：使用实际可见字符或匹配 tokenizer 的估算 token，显示单位及估算标签，不与包含隐藏推理的总输出 token 混算。

P50/P95 等分位数展示样本数和时间窗口，样本不足时提示，不制造平滑后的虚假稳定趋势。跨主机时延尽量使用同一时钟域的单调时钟计算，墙钟时间只用于展示和关联。

### 8.4 费用

优先使用提供方结算字段，或采用适配器认可的互不重复计费类别乘以对应价格。保存 price_revision 和有效时间；重新更新价目表不会静默改写历史账单。

普通输入、缓存读取、不同保留期限的缓存写入、输出和其他计费项按提供方口径处理，不用一个通用公式硬套所有 API。推理 tokens 若已计入输出不得再收费一次。

硬费用预算需要可计算的价格和本次请求消耗上界，发起前预留，结束后按证据结算。无法取得上界时，界面区分“尽力限制的估算预算”和“可强制的调用预算”，不能承诺精确封顶。中断后用量未知的调用保留预留并限制后续支出，等待对账或用户决定，不按 0 释放全部额度。

本地推理可以显示“无 API 账单”，但不写成总成本为零；未配置硬件、电价等真实信息时，不估造电费或折旧。预估费用与已确认费用分开，并注明币种；没有汇率数据不混加不同币种。

### 8.5 看板布局与数据路径

看板包括运行概览、模型与缓存、工具与可靠性、子 agent、硬件与存储、费用。点击统计可下钻到工作区、Run 和 attempt，查看当时配置及失败原因。

调用链写入使用事实 → 用量归一化与去重 → PostgreSQL 明细 → 后台可重建汇总 → ECharts 展示。OpenTelemetry 用于导出跨度和指标，外部系统不是唯一存档；导出失败只重试导出。

Spark 的系统内存和 GPU 统一内存存在重叠，分别标注指标来源与语义，不能把它们简单相加为总占用。不可获得的显存、温度、缓存状态或实时速度显示不可用，不填模拟数值。

## 9. 设置、隐私和生效规则

模型与上下文设置提供当前值、来源、受限原因和生效范围。当前任务接受时冻结模型连接与普通生成参数；新任务解析最新默认，并核对前端 `expected_model` 中展示过的连接及版本。取得生成许可和每次重试后重新编译当前输入、规则、记忆与传输许可。端点/模型变更使能力验证过期，权限收紧约束后续执行，不能用旧快照授权。

能力验证、成本测试和缓存基准必须是可见的显式操作，说明会调用哪个模型、发送什么测试内容和是否收费。不得自动上传用户私密文件做探测，也不得用无意义请求维持命中率。

调试导出默认包含脱敏配置、ID、时间、错误类别和可选日志，不默认包含密钥、全部提示词、记忆正文或截图。用户可以在导出前查看范围。

## 10. 本章验收清单

1. 文本模型与视觉模型之间切换，现有附件和历史处理正确，转换损失可见。
2. 两个同名模型连接保留各自能力、价格与验证证据。
3. 全局、项目和目录 AGENTS.md 范围正确；用户修改或撤销权限后及时生效。
4. 无向量库完成中文关键词定位、按需读取、来源展示和版本编辑。
5. 并发候选与外部 MD 编辑不会互相覆盖；遗忘不会被后台旧候选恢复。
6. 重试的用量分开记录，流式最终事件不会重复记账，未知缓存显示覆盖率缺失。
7. 读缓存命中与缓存创建分开；不为命中省略新的约束。
8. 看板指标来自真实请求和硬件，速度、费用与缓存定义可追溯。
9. 本地模型启动、工具和视觉能力通过实际运行后才将部署状态标为 verified。
