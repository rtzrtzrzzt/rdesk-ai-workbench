# 文件处理、电脑控制与前端交互技术设计

本文隶属于[总体架构](../architecture.md)与[需求说明](../requirements.md)，描述文件如何进入工作台、模型如何使用文件、浏览器与原生桌面如何受控执行，以及用户如何查看、回答、干预和接续长任务。运行状态、事件和数据库事务以[运行时与数据](runtime-and-data.md)为准；模型能力与上下文预算见[模型与上下文](models-and-context.md)；工具授权、重试和未知结果处理见[工具与恢复](tools-and-recovery.md)；安装与真实环境验收见[部署与验证](deployment-and-validation.md)。

## 1. 文档状态、目标和边界

### 1.1 状态声明

本章保留 2026-10-17 批准的产品设计，2026-10-18 已按实现同步。当前已完成真实文件、持久交互、浏览器、受控生成界面等流程；逐项结果与边界见[状态清单](../implementation-status.md)。上游声明、源码接线、辅助检查和本机实际验收分别记录，不能因研究过某个组件就宣称已集成或可用。

目标环境是 DGX Spark ARM64、128GB 统一内存，以原生部署优先；Linux、Windows、macOS 均进入原生设计，先在 Spark 上实测，再在其他系统逐项验证。Docker 仅作为个别可选隔离执行环境，不成为基础文件处理、问答和前端的强制前提。首版产品为单人、多工作区、局域网登录访问；数据库和 API 保留用户归属及工作区授权字段，不能因当前单人而让浏览器直接访问任意服务器文件。

### 1.2 用户应获得的行为

1. 上传、选择或生成文件后，能够看见原件、处理方式、来源位置、版本及限制；解析失败不丢原文件，部分成功不冒充完整成功。
2. 输入格式与模型原生能力分开。文本模型可以读取经过提取的文档文本，但不能因此被标记为“原生支持 PDF、图片或视频”。切换模型时重新预检附件和历史上下文。
3. 阅读、预览、编辑和导出分别定义。能够提取 DOCX 正文不代表可以无损修改 DOCX；能够截图 PDF 不代表理解签章、表单或图表数据。
4. 浏览器自动化、电脑控制是用户按节点、会话和动作范围授权的能力。用户始终看得见控制对象，能够接管和紧急停止。
5. 提问选项是持久任务的一部分。刷新页面、重启服务、断开网络后，用户仍能回答待处理问题；重复点击不能产生重复任务或重复外部操作。
6. 动态 UI 服务于真实任务和真实数据。常规设置、提问、权限确认使用受控组件；自由 HTML/JS 当前禁用，只有具备经过验证的隔离边界后才能启用；生成界面不能绕过后端工具授权。

### 1.3 统一术语

| 术语 | 本章含义 |
| --- | --- |
| Artifact（制品/文件对象） | 由 `artifact_id` 标识的通用二进制或文本对象，包括原件、截图、导出件、预览件和处理结果；不是任意本地路径的别名 |
| Source locator（来源定位） | 能回到原件局部的位置，例如 PDF 页码和框、表格工作表与单元格、音频时间区间；定位粒度不足时必须明说 |
| 派生件 | 由一个或多个原件经转换、OCR、ASR、渲染或编辑产生的新 artifact；有父对象、工具版本和参数记录 |
| BrowserProvider | 提供受控浏览器上下文、页面状态、DOM/可访问性信息、下载等功能的执行适配器 |
| DesktopProvider | 在明确的原生桌面会话里捕获屏幕、使用键鼠或原生可访问性接口的执行适配器 |
| Companion / 节点 | 安装在实际受控电脑上的本地代理进程，负责本机权限、会话绑定、执行、停止及结果回报 |
| 观察代数 | 桌面或浏览器状态世代编号；重连、换屏、接管等使旧观察失效，不以时间戳近似替代 |
| Question | 澄清需求、业务选择、缺失信息等问题，不授予工具权限 |
| Approval | 对具体动作、资源、数据传出等权限请求的接受或拒绝，不能由普通问题的答案代替 |

## 2. 文件能力分层与输入格式矩阵

### 2.1 四层职责

```text
文件入口（上传 / 工作区文件 / 浏览器下载 / 节点传入 / 已生成制品）
    → Artifact 服务：归属、原件、版本、大小、MIME、存储、保留策略
    → FileProcessor：识别 / 提取 / OCR / ASR / 转换 / 预览 / 导出
    → 上下文装配：按任务选段、来源引用、模型能力预检、预算
    → 模型或工具：回答 / 修改计划 / 新版本 / 导出结果
```

Artifact 服务只管对象和授权，不在上传 HTTP 请求中运行重型解析。FileProcessor 是可取消的工具执行任务，复用统一 `run_id / step_id / attempt_id / tool_call_id / operation_id / request_id` 和失败恢复机制；不自行建立另一套 agent 循环。大文件处理排队、资源等待和用户等待沿用公共运行时，解析器内部的页级进度不增加第二套 run 状态。

Docling 作为文档结构提取的重要候选，统一输出文档结构和可引用片段；它不是 Office/PDF 的通用无损编辑器。其官方文档列出多种输入，并把旧二进制 Office、RTF 的处理与 LibreOffice 依赖关联；其文档输出与原始 Office 编辑是不同能力。以实施时锁定版本重新核对的[官方支持格式表](https://docling-project.github.io/docling/usage/supported_formats/)为准。

### 2.2 格式矩阵的解释

下表均为本工作台的设计目标，而非当前已实现支持列表。单元格中的库是应评估的适配候选；启用某行前必须完成该版本在目标平台上的安装和代表性实测。所有编辑默认产生新版本，预览默认只读。复杂排版是否保留要以真实原件与生成件比较，不能从扩展名推导。

| 输入类别 | 读取 / 提取 | 预览 | 编辑 / 新建 / 导出边界 | 路线与启用条件 |
| --- | --- | --- | --- | --- |
| TXT、源码、日志、Markdown | 编码识别、分段、行号；保持原换行及明确解码错误 | 文本、代码高亮、受限 Markdown | 文本范围编辑、差异审阅、原格式或指定编码导出 | 基础阶段；优先标准库和已有编辑组件 |
| CSV / TSV / JSON / JSONL / YAML / TOML / XML | 结构解析与原文并存；表头、记录、字段或路径定位 | 表格 / 树 / 原文切换；大数据分页 | 按 schema 或指定范围修改；重新序列化可能改变空白，提交前显示差异 | 基础阶段；安全解析，不执行标签、不加载 XML 外部实体 |
| HTML / XHTML / MHTML | 正文、链接、资源引用；离线快照与在线页面区分 | 清理后的静态预览；原站交互另开受控浏览器 | 可生成 HTML 或源文件编辑；不把抓取结果视为完整网站克隆 | 基础阶段；禁止自动加载远程资源或执行脚本 |
| PDF（有文本层） | 按页文本、表格、图片、版面；记录段落与页位置 | 隔离的 PDF 查看器、页缩略图和引用跳转 | 新 PDF、批注副本、合并拆分等由专用工具处理；正文重排不能承诺无损 | 基础读取与预览；复杂编辑在专用处理阶段启用 |
| PDF（扫描、混合页） | 检测文本层，按页选择 OCR；避免重复混入原文字层 | 原页与 OCR 文本对照 | OCR 文本导出或带文本层副本；印章、签名、表单需另验 | 文档增强阶段；本地 OCR 引擎与语言包按需安装 |
| DOCX | 段落、表格、标题、可提取的附属对象，结构提取与版面渲染分离 | 转换出的 PDF/HTML，并标出转换来源 | python-docx 等候选做限定结构编辑；复杂修订、域、浮动对象、宏等不能默认保留 | 文档阶段；原件和转换副本始终保留 |
| XLSX | 工作表、单元格、类型、公式文本与缓存值分开；不默认重算 | 范围分页、公式栏、转换预览 | openpyxl 等候选做范围写入；新工作簿导出；Excel 特性与公式重算需专门验收 | 文档阶段；不执行宏，不伪造缺失公式结果 |
| PPTX | 幻灯片文本、形状、表格、备注等按能力提取 | PDF/图片缩略图，显示字体和转换警告 | python-pptx 等候选生成或限定修改；复杂母版、动画、媒体保真另验 | 文档阶段；建立页/形状定位 |
| DOC / XLS / PPT / RTF | 通过 LibreOffice 转换后进入对应结构路径 | 转换预览及兼容警告 | 优先导出新 OOXML/PDF 副本；返回旧格式是额外转换，不承诺回环无损 | 兼容转换阶段；LibreOffice 按需安装 |
| ODT / ODS / ODP | Docling 或格式专用适配器提取结构 | LibreOffice 等生成预览 | 原生格式专用编辑或转换副本；样式兼容逐项验证 | 文档与兼容阶段 |
| Pages / Numbers / Keynote | iWork 可选提取适配；内嵌预览与真实正文区分 | 有内嵌预览则使用；其余走受支持的转换路径 | 不以提取能力承诺原生无损写回；可导出中间结构或新格式 | 扩展格式阶段；对应额外依赖与版本实测 |
| PNG / JPEG / TIFF / BMP / WEBP 等位图 | 元数据、尺寸、帧/页、OCR；模型视觉输入另走能力预检 | 安全解码缩略图、局部放大、多页切换 | 常规裁剪、缩放、格式转换由图像库；生成式编辑需独立模型/服务授权 | 基础预览；OCR、生成式编辑按能力启用 |
| SVG | XML 结构、文本、尺寸和外链；保持原文件 | 去脚本、去外链后的隔离预览 | 源码/受控矢量操作；不把栅格化预览当矢量编辑 | 基础源文件；安全预览需专门策略 |
| 音频 | 元数据、声道、时长；ASR 产生带时间段文本 | 播放器与时间引用；无法解码时保留原件 | FFmpeg 剪切/转码；转写编辑产生文本版本，不能改变原录音事实 | 媒体阶段；编解码器、ASR 权重与授权按需准备 |
| 视频 | 元数据、字幕、音轨；按计划抽帧与 ASR，分别记录信息范围 | 播放器、时间轴、已分析片段 | FFmpeg 裁剪/拼接/转码；不能由几帧推断看完全部视频 | 媒体阶段；视听原生模型能力单独验收 |
| SRT / WebVTT | 时间码、文本、语种；检测时序异常 | 与授权媒体联动 | 文本与时序编辑、字幕格式导出 | 媒体阶段 |
| EML / MSG | 邮件正文、头字段、附件清单；附件独立入库 | 清理后的邮件正文与附件列表 | 可生成新邮件文件或草稿；发送必须走独立授权工具 | 扩展格式阶段；不自动点击追踪链接 |
| EPUB / AsciiDoc / LaTeX | 章节、资源、标记文本；结构与最终排版区分 | 安全 HTML 或受控渲染件 | 源文件编辑、章节导出；TeX 编译为可选隔离任务，禁止默认 shell escape | 扩展格式阶段 |
| ZIP / TAR / GZ 等归档 | 先列表与大小，按授权解包；嵌套包有预算 | 条目树、逐项预览 | 在任务临时目录重打包为新 artifact；不覆盖工作区 | 基础安全列表；解包能力通过安全验收后启用 |
| SQLite / Parquet / Arrow 等数据文件 | 专用只读适配器、schema、分页和范围读取；原数据不全塞上下文 | 表格、查询结果、字段与来源 | 通过授权数据工具写出新文件；原位数据修改有单独事务与审阅 | 数据适配阶段；按任务实际安装依赖 |
| HDF5 / NetCDF / 地理、CAD、3D 等专业格式 | 本版提供格式探测、原件保留和适配器入口；具体解析需明确格式与样本 | 仅展示已有可信预览；不生成虚构内容 | 不承诺尚未选定插件的专业格式编辑；新增适配器另行确认其读取/导出范围 | 扩展边界，按实际需求选择成熟插件，不作为无限格式覆盖承诺 |
| Docling JSON、行业 XML、AFP 等结构格式 | 按锁定版本的明确 schema 适配；不把任意 XML 当已支持行业结构 | 树、来源及可用页面预览 | 以对应 schema 或中间结构导出；资源引用仍走路径授权 | 扩展格式阶段；拒绝未经授权的本地资源跟随 |
| 无法识别或暂未安装适配器的文件 | 保存原件，显示探测结果与原因 | 能安全生成的元数据，不虚构内容 | 用户可选择安装明确依赖、指定兼容工具或仅保留附件 | 全阶段有明确失败 UX；“已上传”与“可解析”分别呈现 |

文件覆盖采用“明确清单 + 可扩展适配器 + 可解释降级”。本版实现常见文档、结构文件、图片、媒体与表中已选路线的能力；未选定具体适配器的专业格式保留原件、能力提示与扩展入口。不能把“任意文件均可准确理解、无损编辑”设为不可验收的承诺，也不能用扩展入口代替清单中已纳入的常见功能。

### 2.3 依赖与 ARM64 策略

FileProcessor 使用注册表声明处理器的输入 MIME、操作种类、依赖、架构、可用执行设备、资源估算方式、取消机制及已验收版本；启动时进行不含推理的可用性检查。没有安装可选组件时，返回“缺少 LibreOffice/OCR/ASR/编解码器”等可执行修复信息，不在任务中静默安装或联网下载模型。

| 组件层 | 候选与用途 | 纳入原则 | Spark/跨平台核实点 |
| --- | --- | --- | --- |
| 标准和轻量解析 | Python 标准库、项目已有文本/结构库 | 能满足任务即复用，不为读文本引入完整文档框架 | 编码、文件锁、路径和换行在三个系统上的差异 |
| 文档结构 | Docling | 以结构、表格、版面、来源为中心，按格式选择，文本不必绕行 OCR | ARM64 包安装、OCR 后端、Torch/推理依赖、内存峰值均待真实验收 |
| Office 转换/渲染 | LibreOffice headless | 独立进程、临时用户配置目录、只输出派生件 | ARM64 可用包、字体、超时/僵死进程、平台转换差异 |
| 专用写入 | python-docx、openpyxl、python-pptx 等候选 | 只开放经验收的操作；复杂保真不由库名担保 | 公式、嵌入物、母版、修订、字体与重算行为 |
| PDF/图像 | 目标操作对应的现有 PDF 工具、Pillow 等候选 | 解析、渲染、编辑分开选择；引入前核对许可证 | PDF 引擎许可、超大像素图、异常字体和本地库支持 |
| OCR | Docling 可接入的 OCR 后端或本机系统 OCR | 语言包可选；保留每页处理路径和实际置信度 | 不假定 x86 GPU 包可在 GB10 使用；CPU 路径也要实测 |
| 音视频 | FFmpeg、ASR 适配器 | 元数据和播放可先启用，转写/抽帧按需启用 | 具体编码器、硬件加速、ASR 后端与权重版本；不默认 CUDA 可用 |
| 专业文件 | 目标格式成熟库或工具 | 有实际需求才装对应插件，保持统一 artifact 接口 | 轮子/系统包、许可、读写完整性及真实文件样本 |

Docling 的安装声明及音视频扩展只构成选择候选的依据；其 ASR extra、含抽帧能力的 `format-video` 扩展及 FFmpeg 等要求见[官方音视频文档](https://docling-project.github.io/docling/usage/processing_audio_media/)。上游支持 ARM64 或提供 ARM64 发行件，不证明某个 OCR/ASR/视觉推理栈已经在 Spark 的 GB10 上端到端可用。

统一内存不等于无限预算。处理器进程与模型共享 128GB 物理内存，重型 OCR、Office 和媒体任务要进入资源调度；优先按页、工作表、时间片分批处理，允许用户缩小范围。精确并发、阈值、速度和峰值必须在部署验收中测量，不在设计阶段填写假定性能。

## 3. 文件对象、来源、版本和处理数据流

### 3.1 对象关系

```text
原件 artifact A（不可覆盖的导入版本）
    ├─ 处理操作 P1 / attempt 1
    │    ├─ 结构化提取 B → 来源片段 → 本次模型上下文引用
    │    └─ 预览 C（PDF / 缩略图 / 音频代理）
    ├─ 处理操作 P2 → OCR / ASR D（注明页或时间范围）
    └─ 用户确认的编辑操作 P3 → 新版本 E
                                      └─ 导出 F
```

运行事实存 PostgreSQL，原始字节存受管理的 artifact 存储；数据库保存对象归属、元数据和存储指针，不把客户端提交的路径直接当作服务器存储位置。大对象默认不放入事件 payload、LangGraph checkpoint 或聊天文本。前端以受授权的流式读取/下载接口获取原件或派生件。

### 3.2 必须表达的数据含义

下表定义语义，最终字段和迁移由[运行时与数据](runtime-and-data.md)统一维护。

| 信息 | 必须记录的含义 | 使用原因 |
| --- | --- | --- |
| 对象身份和归属 | `artifact_id`、所属 `user_id/workspace_id`、创建者和创建时间 | 防止跨工作区读取、重名覆盖和路径猜测 |
| 文件识别 | 原显示名、探测 MIME、声明 MIME、字节数、编码或容器信息 | MIME 冲突可解释；显示名不能控制存储路径 |
| 原件/版本/父对象 | 来源 artifact、版本链、派生操作、是否原件 | 能回溯转换损失与恢复原文件 |
| 产生过程 | `operation_id/attempt_id`、处理器与依赖版本、参数、实际执行设备 | 不同尝试的结果不能混成一次完整处理 |
| 范围与完整性 | 已处理页/表/时间区间、跳过范围、部分成功原因、警告 | 防止“读取了前几页”被回答为“整篇文档” |
| 来源定位 | 原件版本、页码/框、工作表与范围、幻灯片/形状、记录路径、行号或时间段 | 引用点击后回到正确版本和局部 |
| 质量信号 | 工具真正返回的分数、分数含义、缺失状态、校准限制 | 无真实分数时为未知，不由模型编一个百分比 |
| 敏感与传出 | 允许的处理位置、外部 provider 授权范围、保留/删除策略 | 本地解析与外部 OCR/API 有不同数据流 |
| 用户可见性 | 可预览类型、下载权限、失败说明、是否替代版本 | 界面不把内部临时路径暴露为可下载链接 |

来源定位允许多种精度：TXT 是行区间，PDF 是页与可能的 bounding box，XLSX 是工作表与单元格，音视频是时间区间。转换后定位到派生 PDF 页时，还要保存“该页来自原 DOCX 转换”的关系；不能凭重排后页号声称原 DOCX 存在同一页。无可靠坐标时显示“章节/文本段落级来源”，点击打开该范围并提示定位限制。

### 3.3 上传到回答的完整流程

1. 用户在确定的工作区选择文件。客户端先展示文件名、大小及当前模型能力提示；客户端校验只改善体验，后端仍独立验证。
2. 上传请求创建受管理对象，返回 `artifact_id`。上传进度与解析进度分开；上传结束只能显示“原件已保存”。大文件应支持可恢复上传，服务端限制会话归属、总大小、有效期和临时磁盘配额。
3. 后端探测实际类型并执行安全前置检查。用户明确选择范围时保存范围；没有必要时不整包解压、不遍历全部视频、不运行宏。
4. 根据任务与当前模型的 `ModelCapabilityProfile` 预检可用路径。界面给出“原生图片输入”“提取文本”“OCR 文本”“抽帧+音轨转写”等不同标识，细节见[模型与上下文](models-and-context.md)。
5. 缺失依赖或路径不满足时，在不丢附件的前提下提供切换兼容模型、授权转换、安装对应可选组件或缩小范围的操作。若传给外部 API，必须先形成具体数据传出范围并走权限策略。
6. FileProcessor 建立统一工具操作及尝试，按页/块生成结果。用户能看到真实已完成范围，取消会停止继续处理并保留已完成派生件，标为部分结果。
7. 上下文装配只放入任务相关片段、来源和限制；大表先取 schema 与明确范围，长媒体先取时间范围。全文抽取不自动代表全文进入模型。
8. 回答引用对应 artifact 版本及 locator。发生截断、缺页、密码保护、未处理图表等时，在受影响结论附近说明，不只藏在日志中。
9. 文档抽取结果保持为工作区资料；只有用户明确要求记住或既定记忆流程接受后，才写入 Markdown 记忆。资料索引、全文检索与记忆的治理边界见[模型与上下文](models-and-context.md)。

### 3.4 编辑、导出与一致性

编辑前读取当前 artifact 版本；基于旧版本的编辑计划不能自动覆盖新版本。对文本展示 diff；对表格展示表名、范围、原值/新值/公式；对 Office/PDF 提供转换前后预览、影响范围和明确的保真限制。编辑工具先写临时结果，完成基本结构校验后生成新 artifact，再原子更新版本关系。写出文件失败不能使数据库显示新版本已存在。

任务创建导出件后，前端区分“生成成功”与“已下载/已保存到目标路径”。浏览器下载取消或网络中断不能让模型推断已送达。用户要求写回工作区路径时，要以该路径授权、并发版本及文件系统原子替换规则为准；向远端节点保存时由该节点确认实际保存结果。

原件默认保留，派生件可按配置清理，但正在被运行、引用、编辑或导出的版本不能中途删除。删除前显示范围，既有引用遇到过期派生预览时可以重新生成，遇到已删除原件则明确失效，不能悄悄指向同名新文件。工作区关闭、移动与导出应保留可恢复的对象关系。

## 4. 文件失败、安全与资源控制

### 4.1 失败分类及用户界面

| 情形 | 后端行为 | 用户可见结果与可继续路径 |
| --- | --- | --- |
| 类型不支持或依赖缺失 | 保留原件，输出明确能力错误；不盲目换解析器反复重试 | 显示缺什么、支持哪些操作；可选择兼容转换或安装入口 |
| 密码保护 | 不破解、不把密码塞进聊天历史/日志；通过短期敏感输入通道提供给目标处理操作 | 提示输入密码或跳过；失败次数与取消可见；密码不随制品导出 |
| 损坏、格式截断 | 保存解析错误、能定位的失败范围；可保留已提取部分 | 显示“部分解析：哪些范围成功，哪些失败”，可下载原件和部分结果 |
| 超大页/图/归档 | 在危险分配前触发尺寸与解压预算，必要时请求缩小范围 | 显示资源等待或配额限制，提供分段/降分辨率等真实选项 |
| OCR/ASR 质量不稳 | 保留原图/原音、实际识别文本、工具返回质量信号 | 对照查看、手动更正文本副本；不让更正改变原始证据 |
| 外部处理被拒绝 | 不发送数据，保留本地可做的处理结果 | 给出本地路径或明确告知缺失能力；拒绝外传不会触发其他外部 provider |
| 用户取消或进程崩溃 | 停止派发后续块，按公共恢复规则确认子进程与临时输出 | 显示取消中、已取消或需核对；可使用已确认部分，不能假报整件成功 |
| 转换结果与原件不同 | 将字体、页数、对象等可检测差异记入警告 | 用原件/派生件双预览审阅；无法自动比对的部分注明待人工确认 |

### 4.2 安全边界

文件名、MIME 和文档内容均是不可信输入。文档里的提示语、脚本、外部链接或宏不能改变系统指令、扩展工作区权限或授予网络访问。模型提出的文件读取路径也必须走同一工具边界。

- 路径：上传名只作显示；规范化、解析符号链接后再次检查访问根；拒绝越界路径和归档中指向外部的链接，并处理 Windows 路径变体。已有硬链接的全部来源不能仅靠路径判断，任意代码的访问限制仍依赖实际 OS 隔离。授权根目录与打开文件之间应避免路径替换竞争，不能只做字符串前缀比较。
- 归档：先列目录，限制条目数、递归深度、单条和总展开字节、压缩比与耗时；拒绝逃逸路径、设备文件和越界链接。只解入任务专用临时目录，不能直接覆盖用户目录。
- 内容执行：不执行 Office 宏、PDF JavaScript、HTML 脚本或 LaTeX shell escape；外部 XML 实体、远程图片和字体默认不联网取回。
- 解析进程：配置超时、内存、输出和临时磁盘预算；只读访问输入、只写任务输出目录。轻量操作原生运行；高风险复杂转换可选择操作系统沙箱或个别 Docker 任务，不要求整个产品容器化。
- 预览：原始 HTML/SVG/富文本不能直接注入应用 DOM。安全清理和隔离渲染并用；下载响应使用准确内容类型和下载策略，不能让恶意文件继承应用源的权限。
- 外部 API：发送前明确 provider、对象、范围与用途；授权涵盖本次 OCR/ASR/视觉处理才可执行。云端转换失败后不自动改用另一家；截图和原件默认不自动上传。
- 日志：避免记录密码、全量正文、Cookie、令牌；事件引用 artifact 和来源范围。调试需要保留原内容时使用显式受控设置，并尊重工作区保留策略。

## 5. 浏览器控制与原生电脑控制

### 5.1 选择原则与部署拓扑

有稳定 API/文件工具可以达成目标时优先使用对应工具；网页任务优先 BrowserProvider 的 DOM/可访问性信息，必要时才用截图定位。原生应用或无法从 DOM 可靠操作的区域才进入 DesktopProvider。选择依据是目标所需能力与授权，不由模型随意在工具间切换以逃避失败。

```text
访问工作台的浏览器（可能在另一台 Windows/macOS/Linux 电脑）
       │ HTTPS / LAN 登录
       ▼
Spark：FastAPI + LangGraph + 数据库 + 执行调度
       ├─ BrowserProvider → Spark 上隔离的浏览器上下文
       ├─ DesktopProvider → Spark 本机的已授权图形会话
       └─ 已配对节点连接 → 另一台电脑的 companion
                              ├─ 该机 BrowserProvider
                              └─ 该机 DesktopProvider + 本机停止入口
```

在另一台电脑打开工作台网页，不代表 Spark 已获得该电脑桌面或文件系统访问权。控制访问者电脑需要在那台电脑安装、配对并授权 companion；浏览器屏幕共享也不能自动授予键鼠注入。Spark 没有活动图形会话时可使用受控浏览器，不能假定存在可操作的原生桌面。可选专用虚拟桌面与用户当前真实桌面应分别展示，不互相冒充。

### 5.2 两类 Provider 的职责

| 维度 | BrowserProvider | DesktopProvider |
| --- | --- | --- |
| 首选实现方向 | Playwright 的受控浏览器上下文；适配页面和可访问性状态 | 原生 companion，评估 OpenClaw/TryCua 等执行驱动与系统接口 |
| 观察 | URL、标签页、DOM/可访问性节点、定位引用、必要截图 | 当前会话、显示器、窗口、可用可访问性树、截图 |
| 操作 | 导航、按语义定位点击/填写、键盘、滚动、下载上传等受控方法 | 点击、键盘、滚动、拖动、窗口/元素操作，以真实能力声明为准 |
| 会话隔离 | 每工作区/任务明确上下文；临时配置优先，持久登录配置显式选择 | 实际登录用户、OS 图形会话与桌面绑定，无法靠网页标签隔离 |
| 路径 | 下载输出进入 artifact，上传只允许授权 artifact/节点文件 | 本机路径由节点的资源授权控制；后端路径不能直接当节点路径 |
| 降级 | DOM 不可用时可提出截图路径；重新预检模型与权限 | 元素树缺失时只开放明确的屏幕路径，不伪造元素能力 |
| 结果验证 | 导航、字段值、提交后页面状态、下载文件等实际证据 | 新观察、应用实际状态与可查回执；单次键鼠调用返回不等于任务成功 |

Playwright 提供 browser context 隔离概念，实施时复用其[官方上下文机制](https://playwright.dev/docs/browser-contexts)，不通过复制用户日常浏览器配置目录来获得全部登录态。需要接入已有会话时，单独显示该方式的权限和占用范围，不作为默认路径。

模型负责提出受限动作，统一工具执行器负责策略、授权、幂等、预算和结果记录，Provider 只执行明确动作并返回证据。即使借用 OpenClaw/TryCua 的底层驱动，也不引入其 agent 调度或第二套任务循环；LangGraph 是唯一运行时。

### 5.3 开源方案的复用边界

| 方案 | 可参考/复用部分 | 不能直接推定的能力 | 本工作台接入方式 |
| --- | --- | --- | --- |
| OpenClaw | 主机/节点能力声明、配对、屏幕观察与动作契约、OS 权限诊断、接管思路 | 开源项目能运行不等于本工作台已集成；Windows/Linux 当前路径仍有实验性边界 | 选定驱动契约或小范围适配，不部署另一个主 agent 来控制主 agent |
| TryCua | 跨平台 Driver/SDK、原生动作与屏幕处理、平台发布资产 | ARM64 发行件不代表 Spark 桌面验收通过；不同 Wayland 合成器能力不可混用 | 锁定兼容版本，包装为 DesktopProvider；无需采用云端产品或其 agent 循环 |
| Playwright | 页面、上下文、定位、下载与可访问性相关基础能力 | 不能操作任意原生桌面；网页自动化成功不保证网站业务已提交成功 | BrowserProvider 的首选候选；能力由具体浏览器与节点探测 |

资料核实：OpenClaw 当前英文[电脑控制文档](https://docs.openclaw.ai/nodes/computer-use)区分 macOS 原生路径与 Windows/Linux 可选实验路径，要求能力、会话及权限；其具体 SDK/包装方案存在版本演进，部分翻译页面仍为旧实现。因此实施不能混合版本安装指引。TryCua 的[官方发布页](https://github.com/trycua/cua/releases)可见 ARM64 资产及特定 Wayland 组合说明；以目标系统上验证过的版本组合形成安装档案，不把某合成器的通过结论扩展到所有 Linux。

### 5.4 节点注册、配对与能力

1. 用户在目标电脑启动 companion，节点只建立出站连接到配置的工作台地址；LAN 可达不等于自动受信任。
2. 工作台显示短期一次性配对码/挑战、本机名、OS、CPU、会话用户和指纹等可核对信息。用户在两端核对后授权；长期密钥保存在 OS 受保护位置，不能打印在聊天或 URL。
3. 绑定身份与允许的工作区、观察/控制/文件转移范围。修改能力导致权限扩大时需要明确授权变更，旧授权不能随节点升级自动扩大。
4. 节点上报当前实际能力、Provider 版本、OS 权限状态、图形会话、可用显示器、只读/控制支持、文件传输限制、紧急停止状态。缺失字段为未知，不默认为支持。
5. 工作台只对满足本次任务能力与资源授权的节点开放工具。指定节点离线返回该节点不可用，不能改控 Spark 或另一台电脑。
6. 用户可撤销配对或单独撤销控制；节点立即停止接收新输入、使旧观察和租约失效，保留必要审计。已在执行的动作按能力停止和核对，不能假报已撤回外部效果。

能力登记应至少表达屏幕捕获、键鼠注入、窗口/元素观察、后台窗口动作、多显示器、缩放映射、剪贴板、文件传输、取消、查看模式和平台限制。剪贴板、音频、摄像头不因启用屏幕控制而自动开放。锁屏、权限收回、用户注销、会话切换和远程桌面重连都要触发健康变化及观察失效。

### 5.5 平台能力边界

| 平台 | 设计纳入的路径 | 必须真实确认的边界 | 不可替代的授权 |
| --- | --- | --- | --- |
| Linux / Spark | 本机 X11 或受支持图形会话；可选受控浏览器；Wayland 按合成器适配 | 实际 Ubuntu/桌面会话、ARM64 驱动、本机权限、窗口树、捕获与输入是否属于同一会话 | 用户图形会话与 OS 授权；不能用有 `DISPLAY` 证明可控 |
| Linux / Wayland | 通过明确支持的 portal/合成器/驱动组合捕获与输入 | 捕获可用与输入可用分开；XWayland 窗口可用不代表所有原生窗口可用；多屏/后台窗口另验 | portal 交互与会话授权不能由后端绕过 |
| Windows | companion 运行于实际交互用户会话；按 x64/ARM64 适配驱动 | 高 DPI、多屏、UAC/安全桌面、权限级别、服务与用户会话隔离 | 不通过隐藏提权绕过 UAC；受限安全桌面交人工处理 |
| macOS | 原生 companion 与可用驱动；屏幕录制及辅助功能 | 应用签名、TCC 归属、显示器、缩放、窗口和权限撤回 | 屏幕录制、Accessibility 等由用户在 OS 授予，网页无法代授 |

前端设备页逐项显示“可用 / 不可用 / 未知 / 需授权 / 待验收”。平台整体在设计范围内不等于该平台每个动作已通过；将具体组合标明比一个笼统“支持 macOS/Linux/Windows”勾选更准确。

### 5.6 观察、坐标与动作契约

每次观察包含目标节点、Provider/会话代数、显示器或窗口身份、观察标识、捕获时间、原截图 artifact、图像宽高、桌面逻辑尺寸、像素比例、缩放/裁剪变换及观察能力。前端预览缩放不改变模型动作坐标空间。截图缩小、裁剪或旋转后，必须保存可逆映射；无法可靠映射时拒绝输入并重新观察。

DOM/元素引用必须绑定页面或会话代数。页面导航、窗口变化或树重建后旧引用不能复用。坐标动作必须携带观察标识和代数，并由节点在执行前检查：当前目标、屏幕几何、会话及控制租约仍相同。显示器热插拔、DPI 变化、切换 Provider、重连、接管使旧坐标失效；不能只判断“截图在十秒以内”。

动作采用“观察 → 提出动作 → 权限判断 → 执行前重校验 → 执行 → 再观察/核对”顺序。批量连续键鼠动作只能限于已验证的稳定局部，不允许用一张截图规划跨多个变化界面的长点击序列。输入文字先区分普通文本、敏感信息和外传字段；在网页填写凭据即已发生数据传输，不能等点击提交才检查授权。

### 5.7 单桌面写租约、人工接管与紧急停止

单个真实桌面同时只允许一个自动化写入者。根 agent 与最多 3 个子 agent 可以并行读取合法资料，但不能并发争抢同一键鼠。写租约由后端管理并由节点执行校验，绑定 `run_id`、节点、桌面会话、持有者和有效期；失联后不继续接收输入。BrowserProvider 的独立上下文可以单独调度，同一持久登录配置也不能被多个写入者无序共享。

节点提供始终可见的控制指示、本机停止入口和用户明确的接管操作。桌面方案需定义普通人工输入的处理策略：默认检测到用户干预时暂停后续自动输入并提示，避免与用户竞争；可兼容平台做不到可靠检测时，必须要求显式接管，显示限制，不能谎称已能检测。人工接管释放租约并递增观察代数，原排队动作全部失效。恢复必须重新观察并申请/恢复授权范围，不重放旧动作。

紧急停止不能依赖当前模型回复或远端网页连接。节点本机入口应能拒绝新动作、停止或截断可中断动作、释放持续按键/鼠标状态，并回报实际停止结果。原生调用不能及时中断时，显示“停止请求已接收，正在确认当前动作”，由节点监督可结束的驱动进程；不可中断造成的已发生效果保留为待核对，不能宣布绝对未执行。远端“停止任务”与本机紧急停止均进入统一取消状态，但后者优先阻止物理输入。

### 5.8 外部副作用、未知结果和隐私

点击发送、购买、删除、提交表单等可能产生外部效果。超时、断线或进程崩溃后，如果无法证明是否执行，相关 attempt 标为 `outcome_unknown`，走统一结果核对；不能再点一次来“确保成功”。先检查页面回执、目标对象、下载、账号记录或可用 API，能证明成功则补记结果，能证明未执行才重试；无法证明则要求人工确认现状。

权限卡展示准确目标电脑、应用/域名、操作、数据范围和预期影响。业务问题中的“继续”不能当作授权；已覆盖具体范围的授权可以复用，不无故重复询问。屏幕、网页、下载文件中的内容不能授予新权限。外部模型需要截图时，工具先以本地 artifact 保存，只有授权允许向该 provider 发送相应屏幕内容才进入请求；普通截图、桌面预览和执行日志不自动上传。

## 6. 前端页面、布局和信息架构

### 6.1 技术与页面骨架

采用 React、TypeScript、Vite；FastAPI 为单一产品 API 入口，统一前缀 `/api/v1`。前端不直接连模型端口、PostgreSQL、文件路径或驱动 socket。首版局域网登录也采用认证会话、来源检查与工作区授权；具体身份和部署规则见[部署与验证](deployment-and-validation.md)。

```text
顶栏：当前工作区 / 当前线程 / 模型与执行环境 / 连接状态 / 全局停止入口
左侧：工作区切换、线程、后台任务、文件、记忆、工具、设备、设置
中央：对话、任务计划、工具摘要、提问/权限卡、产出与可交互回答
右侧：当前对象检查器（文件预览 / 来源 / 操作详情 / 浏览器或桌面）
底部：输入草稿、附件、能力提示、发送、运行状态、需要用户处理的事项
```

右侧检查器是可收起的，不强制让所有任务占三栏。窄屏改为中央主视图加抽屉，保留停止、问题响应、错误和附件入口。运行信息显示用户可理解的步骤、摘要和证据；不要求也不展示模型原始私有思维链。

### 6.2 页面与主要操作

| 页面/区域 | 用户看到什么 | 主要操作及数据行为 |
| --- | --- | --- |
| 登录与连接 | 目标工作台地址、认证状态、连接错误 | 登录/退出；过期后保留本地草稿，不绕过认证获取缓存中的受限的制品 |
| 工作区首页 | 工作区名称、根目录授权、最近线程、运行与待处理项 | 新建/切换工作区，权限范围始终跟随工作区；不因切换取消后台 run |
| 线程/对话 | 用户消息、助手回答、附件、来源、run 状态和关联任务 | 发送新请求、停止、继续、看差异；文本草稿和待提交附件明确区分 |
| 任务详情 | 根/子任务关系、步骤、尝试、等待原因、产出、操作证据 | 展开失败详情、按策略重试、核对未知结果；步骤重试显示新 attempt，终态 Run 重试创建关联新 Run，不抹旧记录 |
| 后台任务 | 所有工作区有权查看的 queued/running/waiting 状态及完成项 | 筛选、定位、处理问题/权限、取消；离开线程后仍可追踪 |
| 文件库与检查器 | 原件/派生件/版本、格式能力、解析进度、来源、限制 | 上传、预览、选段入任务、编辑审阅、导出、按策略删除 |
| 记忆 | Markdown 文件、作用域、来源、修改历史及规则 | 查看/编辑/审阅；文件解析不会静默出现在记忆中 |
| 工具与扩展 | 启用状态、来源、作用域、版本、授权和缺失依赖 | 启停、配置、查看安装需求；不把普通业务数据作为工具策略 |
| 设备与会话 | Spark/节点、OS、连接、权限、观察/控制能力、租约 | 配对、选择目标、查看、接管、停用控制、撤销配对 |
| 模型与连接 | 连接配置、能力档案、部署状态、可用性与验证状态 | 编辑能力/限额、显式连接测试；保存配置不能暗中触发付费推理 |
| 设置与诊断 | 配置来源、有效值、运行记录、依赖可用性、脱敏日志 | 修改范围清晰；诊断导出先预览敏感字段和内容范围 |

### 6.3 线程中的具体交互

输入框支持多行草稿、粘贴/拖入文件和选择工作区 artifact；可查看每个附件是否上传完成、是否已解析、将以何种模态进入请求。文本输入法组合期间不得因 Enter 意外发送；默认 Enter 发送、Shift+Enter 换行可配置。全局快捷键避开文本编辑和 OS 常用组合，并提供可发现的键盘帮助。

发送动作使用稳定的客户端 `request_id` 和服务端幂等映射。发送中按钮禁用只是体验措施；即使网络重试、双击或刷新，服务端也只能创建同一逻辑请求的一次 run。出现“请求可能已到达”的网络错误时，客户端按 `request_id` 查已有结果，不能再次用新 ID 自动 POST。新线程、追加用户消息、恢复问题与重试失败步骤是不同操作，不能把一切按钮映射为“新建 run”。

任务进行时用户可以继续输入草稿。需要在当前 run 中补充信息时，明确标为补充/纠正并交给运行时的安全边界处理；不把任意新输入静默送入另一个同桌面写入者。取消按钮显示 `cancelling` 直到后端确认，关闭 SSE、关闭标签页或切换工作区均不取消 run。

页面保持用户阅读位置；流式文本到达时，如果用户正在阅读上文，不持续强制滚到底部，显示“有新内容”入口。工具输出默认摘要，原始日志按权限展开；下载、差异、引用都用真实 artifact 关系。失败显示影响范围与可执行的恢复操作，不只显示“出了点问题”。

## 7. 前后端数据流、配置生效与离线行为

### 7.1 状态事实源与事件投影

后端数据库中的 run、question、approval、artifact 等记录是事实源。前端查询取得状态快照及对应事件游标，再通过 SSE 继续接收；公共事件信封为：`schema_version、event_id、run_id、seq、type、occurred_at、payload`。`seq` 在同一 run 内排序，用于去重、缺口检查和重放，不以浏览器时间排序。

```text
用户明确操作 → API 命令（request_id / 版本 / 幂等键）
             → 鉴权与事务 → 数据库事实 + 可重放事件
             → SSE / 兼容协议适配 → 前端投影
断开后       → 按最后 seq 补放；事件已裁剪则拉取新快照
```

前端可以乐观展示“正在提交”，不能先行把后端权威状态改为“已回答/已批准/已成功”。HTTP 响应丢失后查事务结果，事件重复时按 `event_id/seq` 去重，事件缺口时补放。快照与事件连接必须有一致游标，避免“拉完快照、连 SSE 前”的状态丢失。详情见[运行时与数据](runtime-and-data.md)。

界面可以显示 `queued、running、waiting_user、waiting_approval、waiting_resource、cancelling、succeeded、failed、cancelled` 的用户文案。断线是“本页面连接状态”，不创造一个 run 的 `offline` 状态。attempt 展示 `created、running、succeeded、failed、cancelled、outcome_unknown`，不把未知结果染成普通失败后诱导盲目重试。

### 7.2 配置作用域与生效时点

| 配置范围 | 例子 | 生效时点与 UI 说明 |
| --- | --- | --- |
| 安装/服务级 | 监听地址、存储根、数据库、可选驱动 | 需要服务重启的项明确标示，保存不谎称已生效 |
| 用户级 | 语言、主题、键盘偏好、通知 | 纯 UI 立即生效；不改变正在执行操作 |
| 工作区级 | 文件根、工具、Markdown 记忆、外部传输政策、默认模型 | 新 run 使用新版本；权限收回应立即阻止后续受影响操作 |
| 会话编辑状态（不是独立权限层） | 本次选择的模型、输出偏好、资料 | 发送时变为本次 Run 覆盖值；切模型重新预检历史与附件 |
| Run 级 | 模型/工具/预算快照、节点和操作范围 | 创建 run 时固定，运行中变更须形成可审计的明确更新 |
| 节点/会话级 | 屏幕捕获、控制、目标显示器、平台权限 | 由目标节点实际状态确认；权限和几何变化立即使旧观察失效 |

设置页同时显示“继承来源”“当前有效值”“保存后的值”“何时生效”。切换默认模型不会悄悄替换正在运行的模型；收回外部传输权限或桌面控制则不能等到下一个 run 才生效。能力探测是用户可显式发起的操作，有真实测试成本或数据传输时先说明，不把配置保存当推理授权。

### 7.3 断网、后台与刷新

- SSE 断开：显示连接中断及最后更新时间，自动重连与 seq 回放；不取消任务、不重复提交、不把无事件当任务完成。
- 浏览器离线：允许编辑本地草稿和查看合法的已加载内容；涉及写操作的按钮给出不可提交状态。权限答案、桌面动作和外部副作用不积压为“恢复网络后静默发送”。
- 服务重启：前端重新认证并查询任务事实，恢复待处理问题、权限、产出和未知操作；恢复是否继续执行由统一运行时决定，浏览器不自行推断。
- 页面刷新：恢复工作区、线程和未提交草稿；草稿包含敏感正文时的持久化位置与保留策略可配置，凭据不写 localStorage。上传未完成则显示可恢复或需要重选，不伪装上传成功。
- 多标签页：同一个问题可在两页显示，但只有一个答案可被接受；另一页及时切到已回答。桌面写租约不因打开第二页而复制。
- 后台通知：站内待办始终可见，OS/浏览器通知为用户可启用能力；未授权通知不影响任务完成。通知不包含敏感原文或截图。

### 7.4 可访问性与可理解性

受控组件遵循语义化标题、按钮、表单标签、错误关联和可见焦点。选择题使用合适的单选/复选语义；方向键、Tab、Space/Enter 可完成选择与提交；弹窗打开后管理焦点，关闭后回原入口。状态不能只用颜色表达，截图和图表要有文本摘要及可读数据/来源。

动态任务列表和流式输出不会抢夺输入焦点；读屏器以节制的 live region 报告关键状态和“需要回答”，不逐 token 朗读。支持缩放、足够对比度、减少动画、触屏目标和窄屏布局。生成 UI 也遵守组件目录的可访问性约束，宿主提供文本/数据表入口；自由脚本使页面失去响应时的恢复边界见第 9.5 节。

## 8. 持久化提问、选项与答案提交

### 8.1 何时提出问题

模型缺少会实质影响需求、范围或结果的输入时，后端建立 question 并通过 LangGraph interrupt 等待；不是只输出一段带选项的 Markdown，也不是在 React 中挂一个等待中的 Promise。等待时释放模型生成槽，浏览器关闭不影响问题记录。问题可有明确依赖范围，不依赖答案的其他授权步骤仍由调度器判断能否继续。

澄清与权限分离。例如“导出为 XLSX 还是 CSV”是 question；“允许把这个工作簿发送给某外部 API”是 approval。某选项如果同时需要权限，在用户选择后再进入相应权限流程或引用已有有效授权；不能借“推荐选项”暗含授权。

### 8.2 问题记录的语义

| 信息 | 设计约束 |
| --- | --- |
| 身份与归属 | `question_id`，关联 `user_id/workspace_id/thread_id/run_id`，创建步骤和等待位置 |
| 版本 | `version` 单调变化；问题文本、选项或约束实质变化时产生新版本或替代关系 |
| 内容 | 简短标题、问题文本、必要背景、为何需要答案；不暴露模型私有思维链 |
| 输入类型 | 单选、多选、自由文本或受控字段；明确 min/max、长度和 schema |
| 选项 | 每项有稳定 `option_id`、标签与说明，顺序/标签变化不改变其身份 |
| 必填性 | 明确 requiredness，是否允许跳过/取消/保留现状；缺少必填输入不能恢复执行 |
| 默认/推荐 | 可显示建议或预选，但绝不自动提交；超时也不意味着选择默认项 |
| 生命周期 | 待回答、已接受、取消、过期/被替代；旧版本标为 `superseded`，不能继续收答 |
| 受理证据 | 接受的结构化答案、提交者、时间、`request_id`、接受版本和恢复关联 |

问题涉及敏感输入时使用专门敏感字段和最小保留策略，不将密码或 API key 作为普通自由文本答案持久化。question 的业务字段与 approval 的授权范围分开建模，生命周期定义由公共数据模型统一维护。

### 8.3 提交流程与原子性

答案接口固定为 `POST /api/v1/questions/{question_id}/answers`。提交体携带问题版本、稳定选项 ID 或结构化字段、必要自由文本、`request_id`/幂等标识；由后端根据 question 的已保存 schema 验证，不能相信客户端附带的新选项或 requiredness。

1. 前端渲染服务端保存的问题，用户可以选择或填写；未点击提交前只是草稿。
2. 用户提交后显示“正在提交”，保留输入；服务端校验用户/工作区归属、版本、状态和答案约束。
3. 在一个数据库事务中条件接受一次答案，写接受记录、持久化恢复所需状态与可重放通知。提交与恢复投递通过公共一致性机制衔接，避免答案已收而任务永不恢复。
4. 同一 request 重试返回同一接受结果；相同问题已有答案时，不再接受第二个答案，也不重复 resume。多个标签页竞争由数据库条件更新/唯一性约束解决。
5. 已过期或 `superseded` 的版本返回明确冲突，附当前状态或替代问题入口。前端保留用户草稿供复制/对照，不能自动把答案套到新问题。
6. 接受完成只代表答案收妥；恢复后的 run 可能先排队或 `waiting_resource`。UI 分别显示“答案已收到”和“任务已继续”，不让用户再点一次。
7. 网络超时后先按同一 request 查结果或同键重试；不得创建新 run、换 key 重复答题，或把超时视为默认答案。

### 8.4 取消、恢复与用户体验

待回答问题在对话和全局待办均有入口。选择后可修改草稿；提交成功后只读展示接受值。更改已接受的业务决定需要明确的任务补充/修正操作，不编辑历史答案来假装此前未发生过。用户取消 run 时，相关未回答问题同步失效；恢复旧页面不能复活它。

用户可暂停作答、切换页面后回来；如果问题被新的需求替代，显示替代原因及新问题。可选问题的“跳过”是显式答案，不由 UI 自动提交空对象。服务端重启后从持久问题和 checkpoint 恢复等待，不能让前端重新生成问题文本来推断执行位置。

## 9. 受控组件、AG-UI、A2UI 与生成式界面

### 9.1 界面层次与默认路线

| 层 | 作用 | 本工作台的取舍 |
| --- | --- | --- |
| 固定 React 组件 | 产品导航、任务状态、问题、权限、设置、文件与设备 | 核心流程必须由应用维护，具备稳定语义、权限和可访问性 |
| AG-UI | agent 与用户前端间的事件/交互协议 | 可提供版本化适配器；不替代本产品数据库、seq 回放和恢复契约 |
| A2UI | 声明组件、数据绑定和动作的 UI 规范 | 优先用于可信目录内的生成式组合，宿主映射为受控 React 组件 |
| 隔离 HTML/CSS/JS | 复杂交互解释、计算器、图示等 | 当前禁用；尚未具备经过验证的执行资源与禁止出网边界 |

AG-UI 的[官方概览](https://docs.ag-ui.com/introduction)将它定义为连接 agent 与前端的事件协议；A2UI 的[renderer 参考](https://a2ui.org/reference/renderers/)区分消息生成、传输和客户端渲染。研究时该表将 React 对 v0.9.1 的支持列为 Stable，对 v1.0 列为 Planned；不能因为 v1.0 规范为 Candidate 就声称 React v1.0 renderer 已稳定。落地时固定协议、renderer 和组件目录版本，并用适配层迁移。

### 9.2 A2UI 的可信组件目录

组件目录设计覆盖文本、标题、来源、卡片、列表、表格、图表、表单、可折叠详情、步骤、文件链接和有限布局。当前实际允许项由生成界面 DTO 的白名单决定；A2UI 采用 workbench-core 受限目录，不能假定任意官方 renderer 组件或 action 都可使用。每个组件定义 props schema、尺寸/条目限制、可访问性要求、允许的动作及敏感字段策略。模型只能引用目录中的组件名和经过验证的数据，不获得导入 npm 模块、拼接 React 源码或调用宿主对象的权限。

声明 UI 的校验包括协议版本、组件 ID 唯一性、引用完整性、数据类型、循环/深度/数量预算、允许样式、URL 和动作 schema。错误局部可降级为文本/数据表，且显示哪些交互不可用；不能因为一张生成卡片损坏导致整个聊天页失效。增量消息按 surface 版本应用，未完整且未验证的结构先显示占位；已提交的版本与 artifact/回答关联，刷新可恢复。

业务动作使用服务端登记的 `action_id` 和结构化输入，带 surface 版本、业务对象版本与 `request_id`。提交后走 `/api/v1` 的统一命令、鉴权、工具授权和幂等流程。A2UI 按钮写“删除”不会使其获得删除权限，组件本地状态也不能直接覆写数据库任务状态。纯筛选、展开、缩放等本地动作可在前端运行；会改业务事实或启动工具的动作必须经过后端。

图表和对比表绑定真实 query/artifact/工具结果，显示单位、范围、采集/查询时间和已知缺失。用户手动输入的计算参数与来自资料的数据明确区分。没有真实数据时显示缺失项、请求提供数据或只提供说明，不生成看似真实的样例业务数值。数据更新后形成可追踪的新结果版本，不静默改写旧回答证据。

### 9.3 AG-UI 适配与持久状态

内部事件先持久化，再映射到 AG-UI 的文本、工具、状态或自定义事件；协议客户端的 run/stream 完成只说明该适配流的状态，最终产品 run 状态仍从数据库读取。任何适配器都必须保留原 `run_id` 与应用 seq 的关联，不能让前端误把重连重放当新任务。

AG-UI 标准 interrupt 或 CopilotKit hooks 可以帮助渲染等待交互，但 question、answer、approval 的版本与一次接受必须在后端完成。不能使用前端 Promise 作为唯一等待记录，也不能以共享 UI state 的客户端写入代替授权状态变更。若某协议版本无法表达全部产品状态，通过受控扩展事件和查询接口补足，不扭曲公共状态枚举。

默认产品路线是现有 React 组件 + 本产品 API/SSE + 可选开放协议适配，避免为接入一个 UI 库引入另一个主要运行时。需要 CopilotKit 时可评估适配现有 FastAPI 的 OSS Runtime 路径及其运维成本，再决定是否采纳。

### 9.4 CopilotKit 与 Open Intelligent UI 的复用决策

CopilotKit v2 的 `useHumanInTheLoop`、`useInterrupt`、组件与 agent 交互模式有参考价值；但当前官方[Self-managed agents 文档](https://docs.copilotkit.ai/backend/self-managed-agents)明确将生产 `selfManagedAgents` 归于 Enterprise Intelligence，`agents__unsafe_dev_only` 为开发用途。不能因为仓库主体为开源就把该生产接入方式视为默认免费依赖，更不能用 development-only 配置交付生产。许可证核实必须针对实际选择的包、版本与接入模式。

[Open Intelligent UI 仓库](https://github.com/CopilotKit/OpenIntelligentUI)提供直接文本、原生组件与隔离交互答案的参考。其默认使用 OpenAI 和 TypeSafe/Jev，不能直接称作纯本地方案；[架构说明](https://github.com/CopilotKit/OpenIntelligentUI/blob/main/docs/architecture.md)中的进程内 checkpointer 不满足本工作台的持久恢复要求。示例查询和演示组件也不建立真实业务数据连接，必须换成本产品已授权的真实数据工具。

| 可借鉴内容 | 落地时必须替换或补齐 |
| --- | --- |
| 按任务选择文本、受控组件或复杂交互解释 | 路由接入本地模型能力、资源与隐私策略；不默认调用 Jev |
| 流式占位、渐进预览、可交互结果 | 本产品 artifact、surface 版本、断线回放、错误降级 |
| 隔离 iframe 和少量宿主回调 | 本地资源、CSP、版本化 bridge、后端动作授权 |
| 用户明确触发后续问题的交互 | 稳定 request、任务关联、重复提交保护与持久状态 |
| 主题和组件组织 | 沿用工作台信息架构与无障碍约束，不照搬演示视觉和样例业务流程 |

### 9.5 可选 HTML/CSS/JS 隔离渲染

**当前状态：未开放自由脚本执行。** 已实现的是固定可信组件、来源文件绑定和受限 A2UI v0.9.1 适配；以下描述的是启用自由脚本前必须满足的条件，不是当前 iframe 已具备的保证。

复杂动态答案以独立 artifact 保存 HTML/CSS/JS、入口、依赖清单、源数据引用、模型/工具来源与生成时间。原件是可审阅内容；展示器通过隔离 iframe 渲染，不插入主应用 DOM。采用不授予同源身份的 sandbox、严格 CSP 和 Permissions Policy，默认不开放顶层导航、弹窗、下载、摄像头、麦克风和剪贴板；脚本执行须按策略启用，允许能力逐项列出。[iframe 权限语义](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)

iframe 不是完整网络隔离层：sandbox 限制顶层导航，不等于阻止 frame 自身导航；限制资源请求的 CSP 也不能直接当作所有出网路径都已封堵的证明。[HTML sandbox 导航边界](https://html.spec.whatwg.org/multipage/browsers.html#sandboxed-navigation-browsing-context-flag) 因此，禁止外发的模式默认使用可信组件或经过清理、移除主动内容及导航入口的静态预览；没有满足该网络策略并经过验证的执行环境时，不运行自由生成脚本，保留源码与替代显示。不得把“资源放在本地”写成“脚本绝不会访问外网”。

所有所需脚本、字体和图像优先随本地制品提供，不能复制示例里的 CDN/importmap 使本地任务暗中访问外网。依赖进入受控清单，禁止模型自己在线安装任意包。无外网或缺失资源时显示明确降级，主应用仍可查看文本、数据与代码产出。

宿主 bridge 只接受固定消息：受控高度调整、表达明确的后续提问、请求打开允许链接、已注册的业务动作等。消息校验包括 iframe 实例、通道/nonce、schema、大小、速率与关联 surface 版本；不接收任意 URL 抓取、任意文件路径、eval、宿主 JavaScript 或 SQL。隔离源可能是 `null`，不能只比对 origin 字符串；要绑定对应 frame 的消息端口/来源和一次会话标识。

打开外链先在宿主显示域名和数据意图，按链接策略处理。后续提问把所选值明确包含在输入中，通过正常 API 新建对应 turn 或补充任务；不能直接调用模型端口。改变业务数据的动作必须走后端授权；读出秘密、会话 token、工作区路径或浏览器存储不属于 bridge 能力。

生成页面本地控件的状态只属于该 UI。若需要刷新后恢复，声明可序列化的有限状态 schema，单独保存版本；不能序列化任意 DOM 或 JS 闭包。新回答产生新的 surface 快照，旧回答不自动跨调用修改 DOM；需要更新时通过显式版本化动作和后端结果生成新版本。

sandbox 的权限隔离不提供可由工作台保证的独立进程、CPU 或内存配额。浏览器的进程隔离另有实现与站点条件，不能据此承诺异常脚本只影响 iframe。[Chromium Site Isolation](https://www.chromium.org/Home/chromium-security/site-isolation/) 制品大小、同时预览数量、消息速率和心跳用于限制负载与发现异常，宿主超时回调不是任意脚本的硬中止保证。

宿主在正常响应时提供关闭预览、减少动画和切回文本；若浏览器页失去响应，可能需要关闭后重新打开。重新打开只恢复卡片与经过校验的有限状态，自由脚本需用户再次点击运行，避免自动重跑问题制品。后端任务状态独立持久化，页面恢复后查询真实状态，不因预览异常重新提交 Run。

## 11. 必要验证与真实产品验收

### 11.1 辅助验证应回答的具体问题

API/单元/契约检查只验证本次行为约束，不替代真实 UI。重点包括：artifact 归属与跨工作区拒绝；来源和版本链；question 一次接受及恢复投递；request 幂等；SSE 缺口重放；路径/归档越界；取消后不发布未完成结果；桌面代数与租约；未知副作用不自动重试；生成组件 schema 和 bridge 拒绝越权。

用可检查的真实样本核对格式处理，不用伪造“成功率”。路径越界、损坏文件和竞争事务等边界检查使用已获授权的样本与操作；需要合成夹具时另行说明用途并取得授权，不用其输出代替真实业务、模型效果或平台验收。性能只报告测量方法、环境、版本、样本和实际结果。

### 11.2 真实 UI 验收场景

| 场景 | 用户实际操作 | 应观察到的结果 |
| --- | --- | --- |
| 普通文件问答 | 登录→选工作区→上传真实文件→选择范围→发问→点击引用 | 原件可取回，处理方式明确，引用跳到对应版本和来源；未处理范围有提示 |
| 能力不匹配 | 给文本模型附图片/视频，再选择转换或换兼容模型 | 附件不丢；原生/转换输入区别明确；没有授权不调用外部 API |
| 文件编辑导出 | 修改真实文本/工作表/文档→审阅差异→生成新版本→下载打开 | 原件保留，变更范围和保真限制可见，下载件可由目标应用打开 |
| 部分/密码/大文件 | 打开受密码保护、部分损坏或超预算文件→提供合法密码/缩小范围/取消 | 不泄露密码；部分结果准确标识；取消可见且无假完整成功 |
| 归档路径安全 | 通过受控测试夹具导入越界条目或过量展开内容 | 拒绝危险条目/预算，工作区外无写入，用户能理解拒绝原因 |
| 持久问题 | 触发问题→选择但不提交→刷新→提交→再次刷新 | 预选不自动提交；待问可恢复；接受后只读且任务恢复/排队状态准确 |
| 重复/过期答案 | 两标签同时回答；旧页回答已被替代问题；提交后断网 | 只接受一次；旧版本有冲突提示和新问题入口；不重复 resume |
| 后台与断线 | 长任务中切工作区、关闭页、重开、断开/恢复 SSE | 任务继续，历史按 seq 补齐，无重复 run；前端连接状态不篡改 run |
| 浏览器操作 | 使用允许域名完成真实目标流程及下载；人为制造提交后断线 | DOM/页面证据可查，下载回到 artifact；提交状态未知时先核对 |
| 远端节点 | 从另一电脑打开网页但未配对，再配对该电脑 | 未配对时不能控制访问者桌面；配对后显示准确节点、权限与会话 |
| 桌面接管与停止 | 在真实受控会话开始操作→人工接管/本机紧急停止→恢复 | 自动输入停止或显示实际待确认状态；旧观察失效；恢复先重新观察 |
| 缩放/换屏/锁屏 | 操作前改变 DPI、显示器或会话、撤回 OS 权限 | 拒绝旧坐标和旧租约，指出平台原因，不误点其他屏幕 |
| A2UI/动态图表 | 用真实资料生成表格/图表→操作→刷新→检查来源 | 值与真实来源一致；动作走正常后端；缺数据不造图；恢复版本正确 |
| 隔离动态页面 | 按策略打开生成 UI→核对越权回调/外发限制→关闭或重开预览 | 越权回调被拒；受保护的宿主数据不可访问；禁止外发时未满足隔离要求的自由脚本不运行；重开不自动重跑脚本或新建任务 |
| 无障碍 | 仅键盘完成上传入口、选项、提交、错误处理、切页和停止 | 焦点清晰、语义与状态可读、无焦点陷阱，缩放后核心操作可达 |

平台验收记录至少包括 OS/版本、CPU 架构、桌面/合成器、Provider/依赖版本、权限状态、显示器/缩放、实际操作范围、观察到的效果、失败与已知限制。没有目标 Windows/macOS 设备或权限时，先完成可做的实现和辅助检查，再列出这几步操作与预期结果，状态写“等待真实环境验证”。
