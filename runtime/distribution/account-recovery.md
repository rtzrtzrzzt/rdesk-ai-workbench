# 本机所有者密码恢复

忘记账号密码后，在持有该安装的数据目录、数据库和系统账户权限的本机终端执行。此入口没有 HTTP 重置接口，也不接受口令参数、环境变量或管道。它只恢复现有唯一 owner，不创建第二个账号。

```sh
./start.sh stop
./start.sh recover-account
./start.sh start
```

Windows 使用对应 `start.ps1` 命令。三个命令必须使用相同的 `WORKBENCH_DATA_DIR`、数据库及监听配置。只从本机交互终端输入两遍新密码（12–1024字符）；恢复入口拒绝 getpass 无法关闭回显时的降级读取。不要把新密码写进命令行、环境、日志或支持工单。

`stop` 必须确认本实例所有受管组件退出。恢复还会独立检查：

- 本实例 launcher 记录为空，配置 TCP 端口明确拒绝连接；超时或地址错误不能视为已停止。
- agent/files/media Worker 均未持有数据库队列所有权锁，没有30秒内心跳或未过期执行租约。
- 命令具有资源关闭记录、匹配 nonce/identity 的原生终态回执，且原生 supervisor 已退出；仅在派发前已取消且没有任何派发计划/回执时允许不存在原生回执。
- MCP 已派发交换有结果、保留传输已确认关闭；浏览器/桌面 session、动作和 writer lease 已安全释放，独立原生执行器已确认退出。

口令输入前先检查一次；提交前在数据库独占维护 gate 内重新检查。若仍有资源未确认关闭，恢复会拒绝，保留真实记录，不按进程名称或裸 PID 杀进程，不伪造关闭回执。先完成正常停止/对账；不要通过修改数据库状态或删除运行记录绕过检查。

`queued`、`held`、等待用户或审批的 Run 只是持久工作流状态，不代表仍有活跃执行器，因此不再单独阻止密码恢复。恢复不改变任何 Run/Job 状态、工作区路径、审批或历史未知结果，也不启动 Worker 或恢复任务。隔离恢复后的 held 任务及未映射工作区仍按产品既有流程单独处理。

成功后只报告撤销的旧会话数量；所有旧会话失效，使用新密码重新登录。凭据保险库保持独立锁定，不改变其主密钥，也不会自动授予模型或外部操作权限。数据库提交失败只报告未确认成功，重新操作前应先核对实例状态。

本轮已通过真实原生 `start.sh` PTY 与独立 PostgreSQL/HTTP 验收：两次提示均关闭 ECHO、输入不在捕获输出中；真实 queued 任务存在时恢复成功、完整任务快照保持一致；恢复前真实会话与真实旧口令均返回401、新口令登录200；真实 files Worker 持有队列锁及非TTY输入均在口令提示前拒绝。这些是原生恢复与 HTTP 机制证据。主 agent 后续已在该隔离实例的实际 WiFi-IP HTTPS 来源完成 Chrome owner 登录，具体证书验证限制见[HTTPS 说明](native-https.md)。Windows/macOS 终端、原生权限及跨设备完整流程仍待真实环境验证。
